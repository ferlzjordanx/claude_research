## Unit 40 — Coding Interview Track

### 1. Learning Objectives

By the end of this unit you will be able to:

1. **Apply** a fixed procedure to every problem: clarify → brute force → pattern → optimize → implement → test → time complexity → space complexity, and **narrate** it aloud.
2. **Recognize** which of 13 patterns a problem needs (arrays/strings, maps/sets, two pointers, sliding window, stacks/queues, linked lists, binary search, trees, graphs, heaps, intervals, backtracking, dynamic programming) from its signals.
3. **Implement** each pattern's template in idiomatic modern Java with correct edge-case handling.
4. **Analyze** time and space complexity before and after implementation, including amortized costs and recursion stack space.
5. **Test** solutions by hand (dry runs) and with JUnit parameterized tests covering empty, single, duplicate, negative, overflow and maximum-size inputs.
6. **Debug** common mistakes: off-by-one, overflow, mutable shared state in backtracking, wrong loop invariants in binary search, missing visited sets in graphs.
7. **Use** the right Java collections for each pattern (`ArrayDeque` over `Stack`, `PriorityQueue` comparators, `HashMap.merge`, `TreeMap` navigation).

### 2. Prerequisite Knowledge

- Big-O notation: O(1), O(log n), O(n), O(n log n), O(n²), O(2ⁿ), O(n!). Amortized analysis (dynamic array append).
- Java collections and their complexities (Unit 39, card 4.2).
- Recursion and the call stack. Java has no tail-call optimization, so deep recursion (≥ ~10⁴ frames by default) risks `StackOverflowError`. Convert to iteration when depth can be large.
- **Input size → target complexity** heuristic (≈ 10⁸ simple operations per second):

| n | Feasible complexity |
|---|---|
| ≤ 10 | O(n!), O(2ⁿ·n) |
| ≤ 20 | O(2ⁿ) |
| ≤ 500 | O(n³) |
| ≤ 5,000 | O(n²) |
| ≤ 10⁶ | O(n log n) |
| ≤ 10⁸ | O(n), O(log n) |

**Java pitfalls to pre-empt:** `int` overflow (`mid = lo + (hi - lo) / 2`; use `long` for sums/products); `Integer` comparisons with `==` outside −128..127; comparator overflow (`(a, b) -> a - b` overflows; use `Integer.compare`); `Arrays.sort(int[])` is dual-pivot quicksort (worst case O(n²) on adversarial input, rarely relevant) while `Arrays.sort(Object[])` is TimSort (stable); `String` immutability (use `StringBuilder`); `char` arithmetic (`c - 'a'`).

### 3. Mental Model

Coding interviews evaluate **how you think**, not just whether the code passes. The interviewer is scoring:

```
Communication  ──  Do I understand what you're doing and why?
Problem solving ── Did you clarify, find a baseline, recognize a pattern, improve it?
Code quality   ──  Is it correct, readable, idiomatic?
Verification   ──  Did you test it yourself, including edge cases?
Analysis       ──  Can you state and justify time/space before and after?
```

The procedure is your protocol:

```
1. CLARIFY     inputs, outputs, constraints (n, value ranges), edge cases, duplicates, sorted?  (2–4 min)
2. BRUTE FORCE state it + its complexity; don't code it unless asked                        (1–2 min)
3. PATTERN     name the signal → pattern ("contiguous subarray + constraint → sliding window")
4. OPTIMIZE    explain the better approach + target complexity BEFORE coding                 (3–5 min)
5. IMPLEMENT   clean code, meaningful names, helper methods                                 (10–15 min)
6. TEST        dry run on an example, then edge cases; fix bugs calmly                      (3–5 min)
7. TIME        justify (loops, recursion tree, amortization)
8. SPACE       auxiliary + recursion stack + output
```

Patterns are **compressed experience**: recognizing the signal saves you from inventing the algorithm under pressure.

### 4. Comprehensive Theory — The Patterns

Each subsection follows: **Signals → Idea → Template → Worked problem (full procedure) → Complexity → Pitfalls → Practice set**.

#### 4.1 Arrays and Strings

*Signals:* in-place modification, prefix/suffix information, counting characters, rotation, matrix traversal.

*Ideas:* prefix sums (`prefix[i+1] = prefix[i] + a[i]` → range sum O(1)); prefix/suffix products; frequency arrays (`int[26]`); in-place overwrite with a write index; difference arrays for range updates.

**Worked problem — Product of Array Except Self** (no division).

- *Clarify:* zeros allowed? (yes) Overflow? (fits in int per constraints) n ≥ 2.
- *Brute force:* for each i, multiply all others. O(n²) time.
- *Pattern:* prefix/suffix products.
- *Optimize:* `answer[i] = prefixProduct(0..i-1) × suffixProduct(i+1..n-1)`. Two passes, O(n), with the output array reused for prefix.

```java
public int[] productExceptSelf(int[] nums) {
    int n = nums.length;
    int[] ans = new int[n];
    ans[0] = 1;
    for (int i = 1; i < n; i++) ans[i] = ans[i - 1] * nums[i - 1];   // prefix products
    int suffix = 1;
    for (int i = n - 1; i >= 0; i--) {
        ans[i] *= suffix;                                              // combine with suffix
        suffix *= nums[i];
    }
    return ans;
}
```

- *Test:* `[1,2,3,4] → [24,12,8,6]`; with one zero `[1,0,3] → [0,3,0]`; two zeros → all zeros.
- *Time* O(n). *Space* O(1) auxiliary (output excluded).

*Pitfalls:* off-by-one in prefix indexing; forgetting `StringBuilder` for string building.
*Practice:* Rotate Array, Longest Common Prefix, Valid Palindrome, Spiral Matrix, Range Sum Query (immutable), Subarray Sum Equals K (prefix + hash map).

#### 4.2 Hash Maps and Sets

*Signals:* "have I seen X?", counting, grouping by a key, complement lookups, deduplication, O(1) membership.

**Worked problem — Two Sum** (return indices).

- *Clarify:* exactly one solution? (yes) Same element twice? (no) Negative numbers? (yes) Sorted? (no).
- *Brute force:* all pairs. O(n²).
- *Pattern:* complement lookup in a hash map.
- *Optimize:* one pass storing value → index. For each x, check whether `target − x` was seen.

```java
public int[] twoSum(int[] nums, int target) {
    Map<Integer, Integer> seen = new HashMap<>();
    for (int i = 0; i < nums.length; i++) {
        Integer j = seen.get(target - nums[i]);
        if (j != null) return new int[]{j, i};
        seen.put(nums[i], i);
    }
    throw new IllegalArgumentException("no solution");
}
```

- *Test:* `[2,7,11,15], 9 → [0,1]`; duplicates `[3,3], 6 → [0,1]` (check before put); negatives.
- *Time* O(n) average. *Space* O(n).

**Grouping idiom:** `map.computeIfAbsent(key, k -> new ArrayList<>()).add(v)`; counting: `map.merge(x, 1, Integer::sum)`.

*Pitfalls:* putting before checking (self-pairing); using mutable objects as keys; `Integer` equality with `==`.
*Practice:* Group Anagrams (key = sorted chars or count signature), Longest Consecutive Sequence (set + start-of-run check, O(n)), Top K Frequent (map + heap or bucket sort), Contains Duplicate II, Isomorphic Strings.

#### 4.3 Two Pointers

*Signals:* sorted array, pairs/triplets, palindromes, in-place partitioning, merging sorted sequences.

*Variants:* opposite ends (moving inward), same direction (fast/slow; read/write), two arrays.

**Worked problem — 3Sum** (unique triplets summing to 0).

- *Clarify:* return values (not indices); unique triplets; n ≤ 3,000.
- *Brute force:* three nested loops + set for uniqueness. O(n³).
- *Pattern:* sort + fix one + two pointers on the rest.
- *Optimize:* O(n²), skipping duplicates.

```java
public List<List<Integer>> threeSum(int[] nums) {
    Arrays.sort(nums);
    List<List<Integer>> out = new ArrayList<>();
    for (int i = 0; i < nums.length - 2; i++) {
        if (i > 0 && nums[i] == nums[i - 1]) continue;       // skip duplicate anchors
        if (nums[i] > 0) break;                               // sorted: no more zero sums
        int lo = i + 1, hi = nums.length - 1;
        while (lo < hi) {
            int sum = nums[i] + nums[lo] + nums[hi];
            if (sum < 0) lo++;
            else if (sum > 0) hi--;
            else {
                out.add(List.of(nums[i], nums[lo], nums[hi]));
                while (lo < hi && nums[lo] == nums[lo + 1]) lo++;   // skip duplicates
                while (lo < hi && nums[hi] == nums[hi - 1]) hi--;
                lo++; hi--;
            }
        }
    }
    return out;
}
```

- *Test:* `[-1,0,1,2,-1,-4] → [[-1,-1,2],[-1,0,1]]`; all zeros `[0,0,0,0] → [[0,0,0]]`; no solution.
- *Time* O(n²) (sort O(n log n) dominated). *Space* O(log n) to O(n) for sorting, excluding output.

*Pitfalls:* duplicate handling; moving the wrong pointer.
*Practice:* Container With Most Water, Remove Duplicates from Sorted Array, Valid Palindrome II, Sort Colors (Dutch flag), Merge Sorted Array (from the end).

#### 4.4 Sliding Window

*Signals:* **contiguous** subarray/substring + an optimization (longest/shortest/count) + a constraint that can be maintained incrementally (sum, distinct count, frequency match).

*Template (variable window):*

```
left = 0
for right in 0..n-1:
    add a[right] to window state
    while window invalid:
        remove a[left]; left++
    update answer with window [left, right]
```

**Worked problem — Longest Substring Without Repeating Characters.**

- *Clarify:* character set (ASCII? Unicode?), empty string → 0.
- *Brute force:* all substrings + uniqueness check. O(n³) or O(n²) with a set.
- *Pattern:* variable sliding window; state = last index of each char.
- *Optimize:* jump `left` past the previous occurrence. O(n).

```java
public int lengthOfLongestSubstring(String s) {
    Map<Character, Integer> last = new HashMap<>();   // or int[128] for ASCII
    int best = 0, left = 0;
    for (int right = 0; right < s.length(); right++) {
        char c = s.charAt(right);
        Integer prev = last.get(c);
        if (prev != null && prev >= left) left = prev + 1;   // only if inside current window
        last.put(c, right);
        best = Math.max(best, right - left + 1);
    }
    return best;
}
```

- *Test:* `"abcabcbb" → 3`, `"bbbbb" → 1`, `"pwwkew" → 3`, `"" → 0`, `"abba" → 2` (the `prev >= left` check matters here).
- *Time* O(n). *Space* O(min(n, alphabet)).

*Pitfalls:* moving `left` backwards; counting when only the max length is needed; using a sliding window when negatives make sums non-monotonic (then use prefix sums + hash map).
*Practice:* Minimum Window Substring, Longest Repeating Character Replacement, Permutation in String, Maximum Average Subarray I (fixed window), Sliding Window Maximum (monotonic deque).

#### 4.5 Stacks and Queues

*Signals:* matching pairs (brackets), "most recent" processing, undo, expression evaluation, **next greater/smaller element** (monotonic stack), BFS (queue), sliding window max (monotonic deque).

*Java:* use `ArrayDeque` (`push/pop/peek` for a stack; `offer/poll` for a queue). `Stack` is a legacy synchronized `Vector` subclass.

**Worked problem — Daily Temperatures** (days until a warmer day).

- *Clarify:* return 0 when no warmer day.
- *Brute force:* for each day scan forward. O(n²).
- *Pattern:* monotonic decreasing stack of indices.
- *Optimize:* each index pushed and popped once, so O(n).

```java
public int[] dailyTemperatures(int[] t) {
    int[] ans = new int[t.length];
    Deque<Integer> stack = new ArrayDeque<>();          // indices, temperatures decreasing
    for (int i = 0; i < t.length; i++) {
        while (!stack.isEmpty() && t[i] > t[stack.peek()]) {
            int j = stack.pop();
            ans[j] = i - j;
        }
        stack.push(i);
    }
    return ans;
}
```

- *Test:* `[73,74,75,71,69,72,76,73] → [1,1,4,2,1,1,0,0]`; strictly decreasing → all 0.
- *Time* O(n) amortized. *Space* O(n).

*Practice:* Valid Parentheses, Min Stack, Evaluate Reverse Polish Notation, Largest Rectangle in Histogram, Implement Queue using Stacks, Asteroid Collision.

#### 4.6 Linked Lists

*Signals:* pointer manipulation, reversal, cycle detection, middle element, merging, k-th from end.

*Techniques:* dummy head node (avoids special cases), fast/slow pointers (middle, cycle: Floyd), reversal with three pointers, gap of k between two pointers.

**Worked problem — Reverse Linked List II** (reverse positions left..right).

- *Clarify:* 1-indexed; left ≤ right; single node.
- *Brute force:* copy values to an array, reverse the subrange, write back. O(n) time, O(n) space.
- *Pattern:* dummy head + in-place reversal of a sublist.

```java
public ListNode reverseBetween(ListNode head, int left, int right) {
    ListNode dummy = new ListNode(0, head);
    ListNode before = dummy;
    for (int i = 1; i < left; i++) before = before.next;     // node before the sublist
    ListNode curr = before.next;
    for (int i = 0; i < right - left; i++) {                 // head-insertion technique
        ListNode moved = curr.next;
        curr.next = moved.next;
        moved.next = before.next;
        before.next = moved;
    }
    return dummy.next;
}
```

- *Test:* `[1,2,3,4,5], 2, 4 → [1,4,3,2,5]`; `left == right` → unchanged; `left = 1` (dummy covers it).
- *Time* O(n). *Space* O(1).

*Pitfalls:* losing references (draw boxes and arrows); null checks with fast pointers (`fast != null && fast.next != null`).
*Practice:* Reverse Linked List, Linked List Cycle II, Merge Two Sorted Lists, Remove Nth Node From End, Reorder List, LRU Cache (hash map + doubly linked list).

#### 4.7 Binary Search

*Signals:* sorted data, "minimum/maximum value such that…", monotonic predicate, O(log n) required, rotated sorted arrays, **binary search on the answer**.

*Template (first true of a monotonic predicate on [lo, hi]):*

```java
int lo = minAnswer, hi = maxAnswer;          // invariant: answer in [lo, hi]
while (lo < hi) {
    int mid = lo + (hi - lo) / 2;            // no overflow
    if (predicate(mid)) hi = mid;            // mid could be the answer
    else lo = mid + 1;                       // answer is right of mid
}
return lo;                                   // lo == hi
```

**Worked problem — Koko Eating Bananas** (minimum speed k to finish in h hours).

- *Clarify:* piles up to 10⁹; h ≥ number of piles.
- *Brute force:* try k = 1, 2, … up to max pile: O(max · n).
- *Pattern:* binary search on the answer; `canFinish(k)` is monotonic (bigger k, fewer hours).

```java
public int minEatingSpeed(int[] piles, int h) {
    int lo = 1, hi = Arrays.stream(piles).max().orElseThrow();
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (hoursNeeded(piles, mid) <= h) hi = mid;
        else lo = mid + 1;
    }
    return lo;
}

private long hoursNeeded(int[] piles, int k) {
    long hours = 0;                                          // long: sum can exceed int
    for (int p : piles) hours += (p + (long) k - 1) / k;     // ceil(p / k) without floating point
    return hours;
}
```

- *Test:* `[3,6,7,11], 8 → 4`; `[30,11,23,4,20], 5 → 30`; single pile.
- *Time* O(n log M). *Space* O(1).

*Pitfalls:* infinite loops (`lo = mid` with `mid` rounding down), overflow, wrong invariant. State the invariant aloud.
*Practice:* Search in Rotated Sorted Array, Find Minimum in Rotated Sorted Array, First and Last Position, Search a 2D Matrix, Capacity to Ship Packages, Median of Two Sorted Arrays (hard).

#### 4.8 Trees

*Signals:* hierarchical data, BST properties, depth/height/diameter, path sums, level order, lowest common ancestor, serialization.

*Traversals:* DFS (pre/in/post-order; recursive or with an explicit stack), BFS (level order with a queue and `size` snapshot). **In-order on a BST = sorted order.**

*Recursion pattern:* "what does each node return to its parent?" (height, sum, validity, a pair). Global answer via a field or a holder when the path doesn't go through the parent (diameter, max path sum).

**Worked problem — Validate Binary Search Tree.**

- *Clarify:* duplicates allowed? (no, strict); values span the full `int` range.
- *Brute force:* for each node, check its whole left subtree < it < whole right subtree. O(n²).
- *Pattern:* DFS passing down valid (low, high) bounds.

```java
public boolean isValidBST(TreeNode root) {
    return valid(root, Long.MIN_VALUE, Long.MAX_VALUE);     // long: values may equal int bounds
}

private boolean valid(TreeNode node, long low, long high) {
    if (node == null) return true;
    if (node.val <= low || node.val >= high) return false;
    return valid(node.left, low, node.val) && valid(node.right, node.val, high);
}
```

- *Test:* `[2,1,3] → true`; `[5,1,4,null,null,3,6] → false` (3 < 5 in right subtree); single node with `Integer.MAX_VALUE`.
- *Time* O(n). *Space* O(h) recursion (O(n) worst for a skewed tree).

*Pitfalls:* only comparing with direct children; `int` bounds; recursion depth on skewed trees.
*Practice:* Maximum Depth, Diameter of Binary Tree, Binary Tree Level Order Traversal, Lowest Common Ancestor (BST and general), Binary Tree Maximum Path Sum, Serialize and Deserialize Binary Tree, Kth Smallest in BST.

#### 4.9 Graphs

*Signals:* relationships, networks, grids, dependencies, connectivity, shortest path, ordering with prerequisites, islands.

*Representations:* adjacency list `Map<Integer, List<Integer>>` or `List<List<Integer>>`; grids implicitly (4/8 directions).

*Algorithms:*

| Need | Algorithm | Complexity |
|---|---|---|
| Reachability, components | DFS/BFS + visited | O(V + E) |
| Shortest path, unweighted | BFS | O(V + E) |
| Shortest path, non-negative weights | Dijkstra (min-heap) | O((V + E) log V) |
| Negative weights | Bellman-Ford | O(V·E) |
| Dependency order, cycle detection (directed) | Topological sort (Kahn's BFS on in-degrees) | O(V + E) |
| Dynamic connectivity | Union-Find (path compression + union by rank) | ~O(α(n)) per op |
| Minimum spanning tree | Kruskal (sort + union-find) / Prim | O(E log E) |

**Worked problem — Course Schedule** (can all courses be finished?).

- *Clarify:* prerequisites as pairs `[a, b]` meaning b → a; may contain cycles; n ≤ 2,000.
- *Brute force:* repeatedly take any course with satisfied prerequisites: O(V·(V+E)).
- *Pattern:* topological sort (Kahn). A cycle exists if not all nodes are processed.

```java
public boolean canFinish(int n, int[][] prerequisites) {
    List<List<Integer>> adj = new ArrayList<>();
    for (int i = 0; i < n; i++) adj.add(new ArrayList<>());
    int[] indegree = new int[n];
    for (int[] p : prerequisites) {
        adj.get(p[1]).add(p[0]);
        indegree[p[0]]++;
    }
    Deque<Integer> ready = new ArrayDeque<>();
    for (int i = 0; i < n; i++) if (indegree[i] == 0) ready.offer(i);
    int taken = 0;
    while (!ready.isEmpty()) {
        int c = ready.poll();
        taken++;
        for (int next : adj.get(c)) {
            if (--indegree[next] == 0) ready.offer(next);
        }
    }
    return taken == n;
}
```

- *Test:* `2, [[1,0]] → true`; `2, [[1,0],[0,1]] → false`; no prerequisites → true; self-loop `[[0,0]]` → false.
- *Time* O(V + E). *Space* O(V + E).

*Pitfalls:* forgetting `visited` (infinite loops); marking visited on dequeue instead of enqueue in BFS (duplicates in queue); recursion depth on big grids.
*Practice:* Number of Islands, Clone Graph, Rotting Oranges (multi-source BFS), Pacific Atlantic Water Flow, Network Delay Time (Dijkstra), Redundant Connection (union-find), Word Ladder (BFS).

#### 4.10 Heaps / Priority Queues

*Signals:* top-k, k-th largest/smallest, merging k sorted lists, scheduling by priority, running median, "always process the smallest/largest next".

*Java:* `PriorityQueue<T>` is a min-heap by default; max-heap via `Comparator.reverseOrder()`. Offer/poll O(log n), peek O(1). Build from a collection in O(n).

**Worked problem — K Closest Points to Origin.**

- *Clarify:* any order output; ties arbitrary; k ≤ n ≤ 10⁴.
- *Brute force:* sort by distance. O(n log n).
- *Pattern:* max-heap of size k (keep the k smallest).
- *Optimize:* O(n log k). (Quickselect gives O(n) average. Mention it.)

```java
public int[][] kClosest(int[][] points, int k) {
    PriorityQueue<int[]> maxHeap = new PriorityQueue<>(
        Comparator.comparingLong((int[] p) -> (long) p[0] * p[0] + (long) p[1] * p[1]).reversed());
    for (int[] p : points) {
        maxHeap.offer(p);
        if (maxHeap.size() > k) maxHeap.poll();     // drop the farthest
    }
    return maxHeap.toArray(new int[0][]);
}
```

- *Test:* `[[1,3],[-2,2]], 1 → [[-2,2]]`; k = n; duplicate distances.
- *Time* O(n log k). *Space* O(k).

*Pitfalls:* comparator overflow with subtraction; using a min-heap of size n when size k suffices.
*Practice:* Kth Largest Element in an Array, Top K Frequent Elements, Merge k Sorted Lists, Find Median from Data Stream (two heaps), Task Scheduler, Meeting Rooms II (heap of end times).

#### 4.11 Intervals

*Signals:* ranges with start/end, overlaps, merging, scheduling rooms, free time, inserting ranges.

*Ideas:* **sort by start** then sweep, merging when `next.start <= current.end`. For "how many overlap at once" use a min-heap of end times or a sweep over sorted start/end events.

**Worked problem — Merge Intervals.**

- *Clarify:* closed intervals; touching intervals (`[1,4],[4,5]`) merge? (yes); unsorted input.
- *Brute force:* repeatedly merge any overlapping pair until none: O(n²) or worse.
- *Pattern:* sort + linear sweep.

```java
public int[][] merge(int[][] intervals) {
    Arrays.sort(intervals, Comparator.comparingInt(a -> a[0]));
    List<int[]> merged = new ArrayList<>();
    for (int[] in : intervals) {
        if (merged.isEmpty() || merged.getLast()[1] < in[0]) {   // getLast(): Java 21 SequencedCollection
            merged.add(new int[]{in[0], in[1]});
        } else {
            merged.getLast()[1] = Math.max(merged.getLast()[1], in[1]);
        }
    }
    return merged.toArray(new int[0][]);
}
```

- *Test:* `[[1,3],[2,6],[8,10],[15,18]] → [[1,6],[8,10],[15,18]]`; nested `[[1,10],[2,3]] → [[1,10]]`; touching; single interval.
- *Time* O(n log n). *Space* O(n) output (+ sort space).

*Practice:* Insert Interval, Non-overlapping Intervals (greedy by end), Meeting Rooms I/II, Interval List Intersections (two pointers), Minimum Number of Arrows to Burst Balloons.

#### 4.12 Backtracking

*Signals:* generate **all** combinations/permutations/subsets/partitions, constraint satisfaction (N-Queens, Sudoku), "return all valid…", small n (≤ 20).

*Template:*

```java
void backtrack(State state, List<Result> out) {
    if (isComplete(state)) { out.add(snapshot(state)); return; }
    for (Choice c : choices(state)) {
        if (!valid(state, c)) continue;      // prune early
        apply(state, c);
        backtrack(state, out);
        undo(state, c);                       // restore exactly
    }
}
```

**Worked problem — Combination Sum** (candidates reusable, unique combinations).

- *Clarify:* distinct positive candidates; target ≤ 40; order within a combination irrelevant.
- *Brute force:* generate all multisets up to target. Exponential either way, so focus on pruning and avoiding duplicates.
- *Pattern:* backtracking with a start index (avoids permutations of the same combination) and sorting for pruning.

```java
public List<List<Integer>> combinationSum(int[] candidates, int target) {
    Arrays.sort(candidates);
    List<List<Integer>> out = new ArrayList<>();
    dfs(candidates, target, 0, new ArrayDeque<>(), out);
    return out;
}

private void dfs(int[] c, int remaining, int start, Deque<Integer> path, List<List<Integer>> out) {
    if (remaining == 0) { out.add(new ArrayList<>(path)); return; }    // snapshot, not the live path
    for (int i = start; i < c.length; i++) {
        if (c[i] > remaining) break;                                    // sorted → prune the rest
        path.addLast(c[i]);
        dfs(c, remaining - c[i], i, path, out);                         // i, not i+1: reuse allowed
        path.removeLast();
    }
}
```

- *Test:* `[2,3,6,7], 7 → [[2,2,3],[7]]`; no solution; target equal to a candidate.
- *Time* exponential: O(N^(T/M + 1)) loosely, where M = min candidate. *Space* O(T/M) recursion depth.

*Pitfalls:* adding the live list (all results end up empty); forgetting to undo; duplicates when input has repeats (sort + `if (i > start && c[i] == c[i-1]) continue`).
*Practice:* Subsets, Permutations, Letter Combinations of a Phone Number, Word Search, Palindrome Partitioning, N-Queens.

#### 4.13 Dynamic Programming

*Signals:* optimal value (min/max/count/feasible) over choices, **overlapping subproblems** and **optimal substructure**, "number of ways", sequences/strings compared (edit distance, LCS), knapsack-like capacity.

*Method (say it aloud):*

1. **State:** what does `dp[i]` (or `dp[i][j]`) mean? Write it in words.
2. **Transition:** how does a state derive from smaller states?
3. **Base cases.**
4. **Order:** iteration order so dependencies are computed first (or memoized recursion top-down).
5. **Answer:** which state(s)?
6. **Space optimization:** keep only the rows/values needed.

**Worked problem — Coin Change** (fewest coins to make amount).

- *Clarify:* unlimited coins; impossible → −1; amount ≤ 10⁴; coins ≤ 12.
- *Brute force:* recursion over choices. Exponential.
- *Pattern:* unbounded knapsack DP. `dp[a]` = min coins to make amount `a`.
- *Transition:* `dp[a] = min over coins c ≤ a of dp[a − c] + 1`.

```java
public int coinChange(int[] coins, int amount) {
    int INF = amount + 1;                         // sentinel larger than any valid answer
    int[] dp = new int[amount + 1];
    Arrays.fill(dp, INF);
    dp[0] = 0;
    for (int a = 1; a <= amount; a++) {
        for (int c : coins) {
            if (c <= a && dp[a - c] + 1 < dp[a]) dp[a] = dp[a - c] + 1;
        }
    }
    return dp[amount] >= INF ? -1 : dp[amount];
}
```

- *Test:* `[1,2,5], 11 → 3`; `[2], 3 → -1`; amount 0 → 0.
- *Time* O(amount × coins). *Space* O(amount).

*Why greedy fails:* coins `[1,3,4]`, amount 6: greedy picks 4+1+1 (3 coins), optimal is 3+3 (2 coins). This makes a good interview talking point.

**2D example — Longest Common Subsequence.** `dp[i][j]` = LCS of `a[0..i)` and `b[0..j)`. If `a[i-1] == b[j-1]`, then `dp[i][j] = dp[i-1][j-1] + 1`, else `max(dp[i-1][j], dp[i][j-1])`. O(mn) time, O(min(m, n)) space with rolling rows.

*Pitfalls:* unclear state definition (the root of most DP bugs); wrong iteration order (0/1 knapsack iterates capacity *downwards* in the 1D version; unbounded iterates upwards); integer overflow when counting ways (use `long` or a modulo).
*Practice:* Climbing Stairs, House Robber, Longest Increasing Subsequence (O(n log n) with patience sorting), Word Break, Unique Paths, Edit Distance, Partition Equal Subset Sum, Decode Ways.

### 5. Internal Mechanics — What the Machine Is Doing

- **Recursion:** each call pushes a frame (locals, return address) on the thread stack (default ~512 KB–1 MB; virtual threads have growable stacks on the heap). Depth n recursion = O(n) space, and you'll get `StackOverflowError` near ~10⁴–10⁵ frames depending on frame size.
- **Boxing:** `Map<Integer, Integer>` boxes keys and values (allocation, cache misses). Primitive arrays (`int[26]`, `int[128]`) are much faster when the domain is small. Mention it as an optimization.
- **`HashMap` resizing:** pre-size (`new HashMap<>(expected * 4 / 3 + 1)`, or `HashMap.newHashMap(expected)` since Java 19) to avoid rehashing in hot paths.
- **`PriorityQueue`:** array-backed binary heap. `remove(Object)` is O(n), so for "decrease key" in Dijkstra push a new entry and skip stale ones on poll.
- **String building:** `String +=` in a loop is O(n²) total copies, while `StringBuilder` is amortized O(n).
- **Sorting:** `Arrays.sort(int[])` uses dual-pivot quicksort (not stable, fine for primitives). `Collections.sort`/`List.sort`/`Arrays.sort(T[])` use TimSort (stable, O(n log n), O(n) on nearly sorted input).

#### Example 2 — Realistic: Sliding window with frequency matching (Minimum Window Substring)

```java
public String minWindow(String s, String t) {
    if (t.isEmpty() || s.length() < t.length()) return "";
    int[] need = new int[128];
    for (char c : t.toCharArray()) need[c]++;
    int missing = t.length();                 // chars still needed (with multiplicity)
    int left = 0, bestStart = 0, bestLen = Integer.MAX_VALUE;

    for (int right = 0; right < s.length(); right++) {
        if (need[s.charAt(right)]-- > 0) missing--;          // this char was needed
        while (missing == 0) {                               // window valid → try to shrink
            if (right - left + 1 < bestLen) { bestLen = right - left + 1; bestStart = left; }
            if (++need[s.charAt(left)] > 0) missing++;       // removing a needed char breaks validity
            left++;
        }
    }
    return bestLen == Integer.MAX_VALUE ? "" : s.substring(bestStart, bestStart + bestLen);
}
```

*Key insight to narrate:* `need[c]` goes negative for surplus characters. `missing` counts only deficits. Each index enters and leaves the window once, so O(|s| + |t|) time and O(1) space (fixed alphabet).

### 7. Comparative Analysis

| Comparison | Choose A when | Choose B when | Trap |
|---|---|---|---|
| Hash map vs sorting + two pointers | Need indices or one pass, unsorted | Need sorted output/uniqueness, O(1) extra space | Sorting destroys original indices |
| Sliding window vs prefix sums + map | Monotonic window validity (non-negative values) | Negatives present / exact-sum counts | Sliding window with negatives |
| BFS vs DFS | Shortest path (unweighted), levels | Exhaustive exploration, connectivity, cycle detection | DFS for shortest path |
| Dijkstra vs BFS | Weighted non-negative edges | Unit weights | Dijkstra with negative weights |
| Heap vs sort | Need top-k from large/streaming data: O(n log k) | Need fully sorted output | Full sort for k ≪ n |
| Heap vs quickselect | Streaming, stable O(n log k) | One-off k-th element, average O(n) | Quickselect worst case O(n²) without randomization |
| Backtracking vs DP | Must enumerate all solutions | Need count/optimum with overlapping subproblems | Backtracking for "number of ways" with n = 100 |
| Top-down memo vs bottom-up DP | Natural recursion, sparse states | Dense states, avoid recursion depth, space optimization | Stack overflow on deep memo recursion |
| Recursion vs iteration (trees) | Clarity, balanced trees | Very deep/skewed trees | `StackOverflowError` |
| `ArrayDeque` vs `Stack`/`LinkedList` | Always for stack/queue | Never (legacy/slow) | Using `Stack` |

### 8. Failure Modes and Debugging

**Failure 1 — Infinite loop in binary search.**

- SYMPTOM: Timeout on `[1,2]`.
- CAUSE: `lo = mid` with `mid = (lo + hi) / 2` rounding down → no progress when `hi = lo + 1`.
- INVESTIGATE: Dry run with two elements; print `lo, mid, hi`.
- FIX: Use the `lo < hi / hi = mid / lo = mid + 1` template, or round up (`mid = lo + (hi - lo + 1) / 2`) when using `lo = mid`.
- PREVENT: Always test sizes 0, 1, 2.

**Failure 2 — Backtracking returns empty lists.**

- CAUSE: `out.add(path)` adds the same mutable list, which is later emptied by `removeLast`.
- FIX: `out.add(new ArrayList<>(path))`.

**Failure 3 — Wrong answer on large inputs.**

- CAUSE: `int` overflow in sums/products/distances, or comparator subtraction.
- FIX: `long`, `Math.addExact` for detection, `Integer.compare`.

**Failure 4 — Graph BFS times out.**

- CAUSE: Marking visited when dequeuing, so the same node is enqueued many times.
- FIX: Mark when enqueuing.

**Failure 5 — DP gives too-large answers.**

- CAUSE: State definition ambiguous ("up to i" vs "ending at i"), or wrong base case (`dp[0]`).
- FIX: Write the state in words, recompute small cases by hand.

**Debugging technique in interviews.** Don't panic-edit. Pick the smallest failing input, dry-run line by line with a table of variables, find the first divergence from your expectation, fix, and re-run the earlier examples.

### 13. Interview Preparation

#### Quick Questions

**Q: When does a sliding window work?**
*Strong answer:* Contiguous ranges where window validity is monotonic: expanding can only make it "more invalid" and shrinking "more valid", as with non-negative sums or distinct-count limits. Otherwise use prefix sums.

**Q: BFS or DFS for the shortest path in an unweighted grid?**
*Strong answer:* BFS. It explores by distance layers, so the first time you reach the target is the shortest.

**Q: Why might greedy fail for coin change?**
*Strong answer:* Locally optimal choices don't guarantee a global optimum for arbitrary denominations (`[1,3,4]`, amount 6).

#### Intermediate Questions

**Q: Explain your binary search invariant.**
*Strong answer:* The answer is always within `[lo, hi]`. Each step shrinks the range while preserving that, and the loop ends when `lo == hi`. State which side `mid` belongs to.
*Trap:* Not knowing why `lo = mid + 1` vs `lo = mid`.

**Q: How do you detect a cycle in a directed graph?**
*Strong answer:* Kahn's algorithm (if processed < V, there's a cycle) or DFS with three colors (back edge to a gray node).

**Q: What's the space complexity of your recursive solution?**
*Strong answer:* Include the recursion stack (O(h) for trees, O(depth) for backtracking) plus auxiliary structures. Exclude output if conventional, and say so.

#### Advanced Questions

**Q: Optimize LIS from O(n²) to O(n log n).**
*Strong answer:* Maintain `tails[k]` = smallest tail of an increasing subsequence of length k+1. For each x, binary-search the first tail ≥ x and replace it (or append). Length of `tails` is the answer. `tails` stays sorted.

**Q: Dijkstra with a binary heap: why lazy deletion?**
*Strong answer:* `PriorityQueue` lacks decrease-key (`remove(Object)` is O(n)). Push duplicates and skip stale ones. That's O((V + E) log E), which is fine.

### 14. Explain-It-at-Three-Levels

**Concept: Dynamic programming**

- *30 seconds:* DP solves problems with overlapping subproblems and optimal substructure by defining a state, a transition from smaller states and base cases, then computing each state once, either top-down with memoization or bottom-up in dependency order.
- *2 minutes:* Walk Coin Change: state, transition, base, order, answer, and why greedy fails. Mention the space optimization.
- *Deep:* Compare top-down vs bottom-up (recursion depth, sparse states), 0/1 vs unbounded knapsack iteration order, reconstructing the solution (parent pointers), complexity as states × transition cost, and recognizing DP on intervals, trees and bitmasks.

**Concept: Sliding window**

- *30 seconds:* For contiguous subarray problems with a monotonic validity condition, expand the right edge and shrink the left edge while invalid. Each element enters and leaves once, so O(n).
- *2 minutes:* Template, state maintenance (counts, last index), the `abba` trap, and when negatives break it.
- *Deep:* Fixed vs variable windows, counting subarrays ("at most k" − "at most k−1"), monotonic deque for window max, and prefix sums + hash map as the alternative.

**Concept: Binary search on the answer**

- *30 seconds:* If feasibility is monotonic in the answer (bigger capacity always works if smaller does), binary-search the answer range, checking feasibility each time: O(log range × check cost).
- *2 minutes:* Koko example, invariant and template, ceiling division.
- *Deep:* Real-valued binary search with fixed iterations, proving monotonicity, and combining with greedy checks.

1. What's the procedure's step order, and which steps must happen before coding?
2. Why is `ArrayDeque` preferred over `Stack`?
3. When does a sliding window fail for "subarray sum equals k"?
4. Why mark nodes visited on enqueue in BFS?
5. What's the time complexity of building a heap from n elements?
6. *Code reading:* What's the bug in `Comparator<int[]> c = (a, b) -> a[0] - b[0];` for values up to ±2³¹?
7. *Code reading:* Why does `out.add(path)` in backtracking produce empty lists?
8. *Code reading:* In `lengthOfLongestSubstring`, why check `prev >= left`?
9. *Debugging:* Binary search hangs for arrays of size 2. Cause?
10. *Debugging:* Dijkstra returns wrong distances with a negative edge. Why?
11. *Design:* Top-k from a stream of 10⁹ events with 1 GB memory. Approach?
12. *Design:* Memoized recursion or bottom-up DP for n = 10⁵ linear states?

#### Knowledge Check Answers

1. Clarify → brute force → pattern → optimize → implement → test → time → space. Clarify, brute force, pattern and the optimized plan (with target complexity) come before coding.
2. `Stack` extends `Vector` (synchronized, legacy, allows indexed access that breaks the abstraction). `ArrayDeque` is faster and is the documented recommendation.
3. When values can be negative, because shrinking or expanding no longer changes the sum monotonically. Use prefix sums with a hash map of counts.
4. To avoid enqueuing the same node multiple times (time and memory blow-up), and because the first time you see it is via a shortest path.
5. O(n) with bottom-up heapify (`PriorityQueue(Collection)`), versus O(n log n) for n offers.
6. Integer overflow in subtraction gives wrong signs. Use `Integer.compare(a[0], b[0])` or `Comparator.comparingInt`.
7. The same list object is added each time and then mutated/emptied by later undo steps. Add a copy.
8. The previous occurrence may be left of the current window (for example `"abba"`), and moving `left` backwards would make the window invalid and the length wrong.
9. `lo = mid` with floor division doesn't progress when `hi = lo + 1` (or `hi` initialized to `length` with `<=` causes out-of-bounds).
10. Dijkstra assumes a finalized node's distance can't improve. Negative edges violate that. Use Bellman-Ford.
11. Approximate counting (Count-Min Sketch + heap of size k, or Space-Saving algorithm), or partitioned exact counting with external aggregation if exactness is required.
12. Bottom-up: recursion depth 10⁵ risks `StackOverflowError` in Java; iteration also allows O(1) space if only previous states are needed.
