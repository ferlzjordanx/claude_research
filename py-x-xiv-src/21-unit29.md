## Unit 29 — LLM Client Architecture and Reliability

### 1. Learning Objectives

By the end of this unit you will be able to:

1. **Design** a provider-neutral LLM client interface (with `typing.Protocol`) and **implement** adapters for at least two providers (for example the Anthropic API and Amazon Bedrock Converse) that return your own domain types.
2. **Implement** configuration and secret handling for models: a model registry with capabilities, limits and prices; environment-driven selection per feature; secrets from a secrets manager; no keys in code or logs.
3. **Classify** failures with a retry taxonomy (transient network, rate limit, overload, server error, timeout, client error, auth, content refusal, truncation, validation) and **decide** retry, repair, fallback or fail for each.
4. **Implement** deadlines, timeouts, retries with backoff and jitter, retry budgets, and a circuit breaker per provider/model.
5. **Implement** fallback models and deterministic fallback responses, and **evaluate** fallback risks (behavior drift, schema differences, cost, data residency).
6. **Implement** token budgets and cost controls: per-request limits, per-tenant/day budgets in Redis, pre-flight estimation and post-hoc settlement.
7. **Implement** safe prompt/output logging: metadata by default, redaction, hashing, sampling, restricted debug capture.
8. **Instrument** the client with metrics and traces for latency, tokens, cost, errors, retries, fallbacks and breaker state.
9. **Prove** behavior under failure with fault-injection tests.

### 2. Prerequisite Knowledge

- Unit 28: request/response shapes, stop reasons, retries, streaming, Pydantic validation.
- `typing.Protocol` (structural subtyping), `dataclasses`/Pydantic models for value objects, `enum`.
- `asyncio`: `asyncio.timeout`, cancellation, `asyncio.Lock`.
- Redis atomic operations and Lua scripts (for shared budgets/limits).
- OpenTelemetry/Prometheus basics: counters, histograms, spans, attributes.

**Refresher: Protocol vs ABC.** A `Protocol` defines the methods a type must have, and any class with matching methods satisfies it (no inheritance needed). That's ideal for adapters around third-party SDKs and for fakes in tests. An `ABC` requires explicit subclassing and can share implementation. Use Protocols for ports and ABCs when you need shared behavior.

### 3. Mental Model

The LLM client is **an outbound gateway**, the same pattern you'd use for any unreliable, expensive third-party dependency, plus model-specific concerns.

```
 features (triage, RAG answer, agent step)
        │  LLMRequest(purpose="triage", messages, max_tokens, schema?, tenant, deadline)
        ▼
 ┌──────────────────────── LLMClient (your code) ───────────────────────────┐
 │ model selection (registry: purpose → primary, fallbacks, limits, prices)  │
 │ budget check (tenant/day tokens, per-request caps)  ── over → deterministic fallback
 │ for candidate in [primary, *fallbacks]:                                    │
 │    breaker open? skip                                                      │
 │    attempt with timeout, retry transient errors (bounded, within deadline)│
 │    classify outcome → success | retry | next candidate | fail             │
 │ validate (schema), settle budget, record metrics/trace, safe log           │
 └───────────────────────────────────────────────────────────────────────────┘
        │ adapter.complete(...) / adapter.stream(...)
        ▼
 AnthropicAdapter    BedrockAdapter    FakeAdapter (tests)    FaultInjectingAdapter (chaos)
```

Design principle: **features describe what they need (purpose, schema, deadline). The client decides how to get it (model, retries, fallback) and proves what happened (metrics, traces).**

### 4. Comprehensive Theory

#### 4.1 Provider Adapters and Interfaces

**Definition.** A *port* (your interface) plus *adapters* (one per provider) that translate between your domain types and the provider's API.

**Why.** Testability (fakes), switching and fallback, central reliability and accounting, and isolation from SDK churn: when a provider SDK changes, one adapter changes.

**Design the interface around your needs, not around one provider.**

```python
class FailureKind(StrEnum):
    RATE_LIMITED = "rate_limited"          # 429
    OVERLOADED = "overloaded"              # 529 / provider "overloaded" / throttling
    SERVER_ERROR = "server_error"          # 5xx

        self.kind, self.provider, self.model = kind, provider, model
        self.retry_after_s = retry_after_s


RETRYABLE = {FailureKind.RATE_LIMITED, FailureKind.OVERLOADED, FailureKind.SERVER_ERROR,

FALLBACK_ELIGIBLE = RETRYABLE | {FailureKind.NOT_FOUND, FailureKind.CONTENT_FILTERED}
```

**Adapters must** map request types, map responses and stop reasons, **translate every provider exception into `LLMError` with the right `FailureKind`**, extract `retry-after`, and never leak SDK types upward.

**Common mistakes.** An interface that's just one provider's API renamed (leaky). A "lowest common denominator" that hides essential features. Instead, expose capabilities explicitly (`supports_structured_output`, `supports_sampling_params`). Letting SDK exceptions escape adapters.

#### 4.2 Configuration, Secrets and Model Selection

**Model registry**: data, not code.

```python
# app/llm/registry.py
from dataclasses import dataclass
from decimal import Decimal


@dataclass(frozen=True)
class ModelSpec:
    key: str                       # stable internal name, e.g. "anthropic:claude-opus-5-5"
    provider: str                  # "anthropic" | "bedrock"
    model_id: str                  # provider's model ID or inference profile ARN
    max_output_tokens: int
    context_tokens: int
    price_in_per_mtok: Decimal
    price_out_per_mtok: Decimal
    supports_structured_output: bool
    supports_sampling_params: bool
    data_region: str               # for residency decisions


@dataclass(frozen=True)
class PurposePolicy:
    purpose: str
    primary: str                   # ModelSpec.key
    fallbacks: tuple[str, ...]     # ordered; every one must be evaluated for this purpose
    timeout_s: float               # per attempt
    deadline_s: float              # total, including retries and fallbacks
    max_attempts_per_model: int
    max_output_tokens: int
    deterministic_fallback: str | None = None   # template text when everything fails
```

Load the registry and policies from configuration (YAML/Pydantic settings, Parameter Store) so you can change routing without deploying code, and **version** the config. Changing a model is a behavior change that needs evaluation (Unit 31 eval sets), so treat config changes like code changes, with review and canary.

**Secrets.** Provider API keys come from Secrets Manager (or IAM for Bedrock), loaded at startup or cached with TTL (Unit 27). Wrap keys in `pydantic.SecretStr` so they don't print in logs and reprs. Rotate keys. Use one key per environment, and ideally per service, so usage and revocation are scoped.

**Model selection** is per *purpose*: triage (fast, cheap model or low effort), RAG answer (stronger model), agent step (strong model with tool use). Pin model versions/IDs. Avoid floating aliases in production unless you accept unannounced behavior changes.

#### 4.3 Retry Taxonomy, Timeouts and Circuit Breakers

**Taxonomy → action.**

| Failure kind | Same model retry? | Fallback? | Notes |
|---|---|---|---|
| CONNECTION, TIMEOUT | Yes (bounded) | Yes after attempts | Idempotent call; check deadline |
| RATE_LIMITED (429) | Yes, honor `retry-after` | Yes (different quota pool) | Also trips client-side limiter |
| OVERLOADED (529/throttling) | Yes with backoff | Yes | Strong signal to fall back quickly |
| SERVER_ERROR (5xx) | Yes | Yes | Count toward breaker |
| BAD_REQUEST (400/413) | **No** | Usually no (your bug); maybe yes if model-specific param unsupported and fallback model differs | Alert: config/code issue |
| AUTH (401/403) | **No** | Maybe (other provider) | Page someone: key revoked/expired |
| NOT_FOUND (model) | No | Yes | Model retired/misconfigured |
| CONTENT_FILTERED / refusal | No | Possibly (policy decision) | Some providers offer server-side refusal fallbacks [Version-dependent] |
| Truncation (`max_tokens`) | Not as-is | No | Adjust request |
| Validation failure | Repair (≤ 1–2) | After repair fails, maybe | Handled above adapter (Unit 28) |

**Where retries belong.** In **one** layer, the client, with full knowledge of the deadline and fallbacks. Disable SDK auto-retries (`max_retries=0`) or configure the SDK and don't retry yourself, but never both. Never retry in nested layers (HTTP client + SDK + your client + caller), because attempts multiply: 3 × 3 × 3 = 27 calls per user request during an outage.

**Backoff.** Exponential with **full jitter**: `sleep = random.uniform(0, min(cap, base × 2^attempt))`. Honor `retry-after` when present, capped by the remaining deadline.

**Retry budget.** Limit retries to a fraction of total traffic (for example ≤ 10% extra calls per minute). When the budget is exhausted, fail fast or fall back. This prevents retry storms from turning a partial outage into a total one.

**Timeouts.** Per-attempt timeout plus overall deadline. Choose per purpose: interactive classification 5–10 s, answers 20–30 s streamed, offline batch longer. Propagate the caller's deadline down (if the HTTP request has 25 s left, don't start a 30 s attempt).

**Circuit breaker.** Per (provider, model). States:

```
CLOSED ──(failure rate > threshold over window, min calls)──▶ OPEN ──(cool-down elapsed)──▶ HALF_OPEN
   ▲                                                                                      │
   └───────────────(probe succeeds)──────────────────────────────────────────────────────┘
                     (probe fails) ──▶ OPEN
```

While OPEN, requests skip that model immediately (no waiting on timeouts), which protects latency, saves quota and gives the provider time to recover. Count only *provider-health* failures (5xx, overload, timeouts, connection), not 400s or refusals.

#### 4.4 Fallback Models and Deterministic Fallback Responses

**Fallback chain.** On fallback-eligible failure, try the next model in the purpose policy: a different model from the same provider (different capacity pool), the same model via a different platform (direct API vs Bedrock), or a different provider.

**Fallback risks (interviewers ask about these).**

- **Behavior drift:** different models follow instructions differently, so quality, tone, safety behavior and refusal rates differ. *Every fallback model must pass the same eval suite for that purpose.*
- **Schema/feature differences:** structured output support, tool-calling format, max output, sampling params. The adapter must adapt or the fallback must be excluded for that purpose.
- **Cost:** a fallback may be more expensive. Budget for failover scenarios.
- **Latency:** cross-region or larger models may be slower.
- **Data residency/compliance:** a fallback in another region or provider may violate data agreements. Encode `data_region` in the registry and filter.
- **Cache loss:** prompt caches are per model, so fallback runs pay full input cost.
- **Silent degradation:** if fallbacks hide outages, quality may drop unnoticed. Alert on the fallback rate.

**Deterministic fallback response.** When all models fail or budgets are exhausted, return a pre-written, safe response: "I can't generate an answer right now. Here are the most relevant help articles: …" (from retrieval only), or create a ticket for a human. It must be honest, clearly labelled as degraded in metrics and traces, and never pretend to be a model answer.

#### 4.5 Token Budgets and Cost Controls

**Levels.**

1. **Per request:** cap `max_output_tokens` per purpose; reject or trim inputs over a token limit (count or estimate before sending).
2. **Per run** (agents, Part XIV): cumulative token budget across steps.
3. **Per tenant/user per period:** daily/monthly token or dollar budgets enforced atomically in Redis. **Reserve** an estimate before the call and **settle** with actual usage after.
4. **Global:** organization spend alarms, provider-side spend limits.

**Estimation.** Use the provider's token-counting endpoint when accuracy matters (pre-flight for large inputs), or a conservative chars/3 heuristic for budgeting. Settle with the actual `usage` returned.

**Cost controls beyond budgets:** prompt caching for stable prefixes (system prompt, tool definitions, large shared context), smaller models or lower effort for simple purposes, response caching for identical deterministic requests (normalized input → cached output, with care for personalization and freshness), batch APIs for offline work (often ~50% cheaper), and trimming history and retrieved context.

#### 4.6 Safe Prompt/Output Logging

**Default:** log *metadata* only: purpose, model, provider, tokens, latency, stop reason, attempts, fallback used, cost, request/trace IDs, provider request ID, tenant (pseudonymous). **Never** log raw prompts or outputs by default. They contain PII, secrets users paste, other customers' data from retrieval, and system prompts.

**When content is needed** (debugging, evaluation): opt-in, sampled capture to a **separate restricted store** with redaction (emails, phones, card numbers, API-key patterns), short retention, access logging, keyed by trace ID. Store **hashes** of prompts (with a secret salt) in normal logs to correlate identical inputs without revealing them.

**Also:** mask secrets in settings (`SecretStr`), scrub exception messages (providers sometimes echo inputs in errors), and don't put content in metric labels or span attributes.

#### 4.7 Observability for the Client

**Metrics (low-cardinality labels: provider, model, purpose, outcome):**

- `llm_requests_total{outcome}` (success, error kind, fallback, deterministic)
- `llm_latency_seconds` histogram (per attempt and end-to-end)
- `llm_tokens_total{type=input|output|cache_read}`
- `llm_cost_usd_total`
- `llm_retries_total`, `llm_fallbacks_total{from,to}`
- `llm_circuit_state{provider,model}` gauge
- `llm_budget_rejections_total`

**Traces:** span per logical call (`llm.call purpose=triage`) with child spans per attempt (`chat claude-opus-5-5`), attributes for model, tokens, stop reason and error kind, and events for retry/fallback/breaker-skip. OpenTelemetry GenAI semantic conventions (`gen_ai.*`) are still in Development status, so centralize attribute names.

**Alerts:** error rate per provider, fallback rate > baseline, breaker open, cost per hour above budget, p95 latency.

### 5. Internal Mechanics

#### 5.1 One call through the client

```
complete(req)
 → policy = policies[req.purpose]; deadline = now + policy.deadline_s (or caller's remaining, whichever smaller)
 → budget.reserve(tenant, estimate)  ── fails → deterministic fallback (metric: budget_rejected)
 → for model_key in [policy.primary, *policy.fallbacks]:
      spec = registry[model_key]; skip if region not allowed or capability missing
      breaker = breakers[model_key]; if breaker.is_open(): record skip; continue
      for attempt in 1..policy.max_attempts_per_model:
          remaining = deadline - now; if remaining <= 0: break out → deterministic fallback
          try: resp = await adapter.complete(spec.model_id, req, timeout=min(policy.timeout_s, remaining))
               breaker.record_success(); budget.settle(actual); metrics/trace; return resp
          except LLMError as e:
               breaker.record_failure() if e.kind in PROVIDER_HEALTH_KINDS
               if e.kind not retryable: break (to next model if fallback-eligible, else raise)
               if not retry_budget.allow(): break
               sleep(backoff(attempt, e.retry_after_s) capped by remaining)
 → all candidates failed → budget.release(); deterministic fallback or raise LLMUnavailable
```

#### 5.2 Circuit breaker internals

A sliding window (count-based or time-based) of outcomes. When `calls ≥ min_calls` and `failure_rate ≥ threshold`, transition to OPEN with `opened_at`. `allow()` returns False until `cooldown` passes, then HALF_OPEN allows a limited number of probe calls. Success closes the breaker, and failure reopens it. In a multi-process deployment each process has its own breaker, which is usually fine (each learns quickly). Shared state via Redis is possible but adds a dependency on the hot path.

```python
# app/llm/fake.py
from collections.abc import AsyncIterator

from app.llm.errors import LLMError
from app.llm.types import LLMRequest, LLMResponse, Usage


class FakeAdapter:
    """Scripted adapter for tests: each call pops the next outcome."""
    provider = "fake"

    def __init__(self, outcomes: list[LLMResponse | LLMError]) -> None:
        self.outcomes = outcomes
        self.calls: list[tuple[str, LLMRequest]] = []

    async def complete(self, model: str, req: LLMRequest, timeout_s: float) -> LLMResponse:
        self.calls.append((model, req))
        outcome = self.outcomes.pop(0)
        if isinstance(outcome, LLMError):
            raise outcome
        return outcome

    async def stream(self, model: str, req: LLMRequest, timeout_s: float) -> AsyncIterator[str]:
        resp = await self.complete(model, req, timeout_s)
        for word in resp.text.split(" "):
            yield word + " "


def ok(text: str = "ok", model: str = "m") -> LLMResponse:
    return LLMResponse(text=text, stop_reason="end", usage=Usage(10, 5), model=model, provider="fake")
```

#### Example 2 — Realistic: Anthropic and Bedrock adapters with error translation

```python
# app/llm/adapters/anthropic_adapter.py
import anthropic

from app.llm.errors import FailureKind, LLMError
from app.llm.types import LLMRequest, LLMResponse, Usage

_STOP = {"end_turn": "end", "stop_sequence": "end", "max_tokens": "max_tokens",
         "refusal": "refusal", "tool_use": "tool_use"}


class AnthropicAdapter:
    provider = "anthropic"

    def __init__(self, client: anthropic.AsyncAnthropic) -> None:
        self._client = client          # constructed with max_retries=0: the LLMClient owns retries

    async def complete(self, model: str, req: LLMRequest, timeout_s: float) -> LLMResponse:
        kwargs: dict = {
            "model": model,
            "max_tokens": req.max_output_tokens,
            "system": req.system,
            "messages": [{"role": m.role.value, "content": m.text} for m in req.messages],
        }
        if req.json_schema is not None:
            kwargs["output_config"] = {"format": {"type": "json_schema", "schema": req.json_schema}}
        try:
            resp = await self._client.with_options(timeout=timeout_s).messages.create(**kwargs)
        except anthropic.RateLimitError as e:
            raise LLMError(FailureKind.RATE_LIMITED, self.provider, model, _retry_after(e)) from e
        except anthropic.APITimeoutError as e:
            raise LLMError(FailureKind.TIMEOUT, self.provider, model) from e
        except anthropic.APIConnectionError as e:
            raise LLMError(FailureKind.CONNECTION, self.provider, model) from e
        except anthropic.AuthenticationError as e:
            raise LLMError(FailureKind.AUTH, self.provider, model) from e
        except anthropic.PermissionDeniedError as e:
            raise LLMError(FailureKind.AUTH, self.provider, model) from e
        except anthropic.NotFoundError as e:
            raise LLMError(FailureKind.NOT_FOUND, self.provider, model) from e
        except anthropic.BadRequestError as e:
            raise LLMError(FailureKind.BAD_REQUEST, self.provider, model, detail=str(getattr(e, "type", ""))) from e
        except anthropic.APIStatusError as e:
            kind = FailureKind.OVERLOADED if e.status_code == 529 else (
                FailureKind.SERVER_ERROR if e.status_code >= 500 else FailureKind.BAD_REQUEST)
            raise LLMError(kind, self.provider, model, _retry_after(e)) from e

        text = "".join(b.text for b in resp.content if b.type == "text")
        stop = _STOP.get(resp.stop_reason or "", "other")
        if stop == "refusal":
            raise LLMError(FailureKind.CONTENT_FILTERED, self.provider, model)
        u = resp.usage
        return LLMResponse(
            text=text, stop_reason=stop, model=model, provider=self.provider,
            usage=Usage(u.input_tokens, u.output_tokens,
                        getattr(u, "cache_read_input_tokens", 0) or 0,
                        getattr(u, "cache_creation_input_tokens", 0) or 0),
            provider_request_id=getattr(resp, "_request_id", None),
        )

    async def stream(self, model, req, timeout_s):   # analogous with messages.stream(); omitted for brevity
        raise NotImplementedError


def _retry_after(e: anthropic.APIStatusError) -> float | None:
    value = e.response.headers.get("retry-after") if e.response is not None else None
    try:
        return float(value) if value else None
    except ValueError:
        return None
```

```python
# app/llm/adapters/bedrock_adapter.py
import anyio
import boto3
from botocore.config import Config
from botocore.exceptions import ClientError, ConnectTimeoutError, EndpointConnectionError, ReadTimeoutError

from app.llm.errors import FailureKind, LLMError
from app.llm.types import LLMRequest, LLMResponse, Usage

_KIND = {
    "ThrottlingException": FailureKind.RATE_LIMITED,
    "ServiceUnavailableException": FailureKind.OVERLOADED,
    "ModelNotReadyException": FailureKind.OVERLOADED,
    "InternalServerException": FailureKind.SERVER_ERROR,
    "ModelTimeoutException": FailureKind.TIMEOUT,
    "AccessDeniedException": FailureKind.AUTH,
    "ResourceNotFoundException": FailureKind.NOT_FOUND,
    "ValidationException": FailureKind.BAD_REQUEST,
}
_STOP = {"end_turn": "end", "stop_sequence": "end", "max_tokens": "max_tokens",
         "tool_use": "tool_use", "guardrail_intervened": "refusal", "content_filtered": "refusal"}


class BedrockAdapter:
    provider = "bedrock"

    def __init__(self, region: str) -> None:
        self._client = boto3.client("bedrock-runtime", region_name=region,
                                    config=Config(retries={"max_attempts": 1, "mode": "standard"}))

    async def complete(self, model: str, req: LLMRequest, timeout_s: float) -> LLMResponse:
        def call() -> dict:
            return self._client.converse(
                modelId=model,
                system=[{"text": req.system}],
                messages=[{"role": m.role.value, "content": [{"text": m.text}]} for m in req.messages],
                inferenceConfig={"maxTokens": req.max_output_tokens},
            )
        try:
            with anyio.fail_after(timeout_s):
                resp = await anyio.to_thread.run_sync(call)     # boto3 is sync: don't block the loop
        except TimeoutError as e:
            raise LLMError(FailureKind.TIMEOUT, self.provider, model) from e
        except (ConnectTimeoutError, ReadTimeoutError) as e:
            raise LLMError(FailureKind.TIMEOUT, self.provider, model) from e
        except EndpointConnectionError as e:
            raise LLMError(FailureKind.CONNECTION, self.provider, model) from e
        except ClientError as e:
            code = e.response["Error"]["Code"]
            raise LLMError(_KIND.get(code, FailureKind.SERVER_ERROR), self.provider, model, detail=code) from e

        stop = _STOP.get(resp.get("stopReason", ""), "other")
        if stop == "refusal":
            raise LLMError(FailureKind.CONTENT_FILTERED, self.provider, model)
        text = "".join(b.get("text", "") for b in resp["output"]["message"]["content"])
        u = resp["usage"]
        return LLMResponse(text=text, stop_reason=stop, model=model, provider=self.provider,
                           usage=Usage(u["inputTokens"], u["outputTokens"],
                                       u.get("cacheReadInputTokens", 0), u.get("cacheWriteInputTokens", 0)),
                           provider_request_id=resp.get("ResponseMetadata", {}).get("RequestId"))

    async def stream(self, model, req, timeout_s):
        raise NotImplementedError
```

**Notes.**

- `anyio.fail_after` around a thread doesn't kill the thread. The boto3 call continues in the background until its own read timeout. Configure botocore's `read_timeout` to roughly match.
- Structured output via Bedrock may differ per model (tool-based JSON or provider-native options). Mark capability per model in the registry and let the client skip models that can't satisfy a schema request.
- Both adapters raise only `LLMError`. Upper layers never import provider SDKs.

#### Example 3 — Production-oriented: Client with deadlines, retries, breaker, fallback, budgets, metrics and safe logging

```python
# app/llm/breaker.py
import time
from collections import deque
from dataclasses import dataclass, field


@dataclass
class CircuitBreaker:
    failure_threshold: float = 0.5
    min_calls: int = 10
    window: int = 50
    cooldown_s: float = 30.0
    half_open_probes: int = 2
    _outcomes: deque[bool] = field(default_factory=lambda: deque(maxlen=50))
    _opened_at: float | None = None
    _probes_left: int = 0

    def allow(self) -> bool:
        if self._opened_at is None:
            return True
        if time.monotonic() - self._opened_at >= self.cooldown_s:
            if self._probes_left > 0:
                self._probes_left -= 1
                return True                      # HALF_OPEN probe
            return False
        return False

    @property
    def state(self) -> str:
        if self._opened_at is None:
            return "closed"
        return "half_open" if time.monotonic() - self._opened_at >= self.cooldown_s else "open"

    def record(self, success: bool) -> None:
        if self._opened_at is not None:          # result of a probe
            if success:
                self._opened_at, self._outcomes = None, deque(maxlen=self.window)
            else:
                self._opened_at, self._probes_left = time.monotonic(), self.half_open_probes
            return
        self._outcomes.append(success)
        if len(self._outcomes) >= self.min_calls:
            failure_rate = self._outcomes.count(False) / len(self._outcomes)
            if failure_rate >= self.failure_threshold:
                self._opened_at, self._probes_left = time.monotonic(), self.half_open_probes
```

(Single event loop per process, so no lock is needed for this in-memory breaker in async code. With threads, add a lock.)

```python
from redis.asyncio import Redis

RESERVE_LUA = """
local used = tonumber(redis.call('GET', KEYS[1]) or '0')
local limit = tonumber(ARGV[1]); local amount = tonumber(ARGV[2])
if used + amount > limit then return -1 end
local new = redis.call('INCRBY', KEYS[1], amount)
redis.call('EXPIRE', KEYS[1], 172800)
return new
"""


class TenantTokenBudget:
    def __init__(self, redis: Redis, daily_limit: int) -> None:
        self._redis, self._limit = redis, daily_limit
        self._reserve = redis.register_script(RESERVE_LUA)

    def _key(self, tenant: str, day: str) -> str:
        return f"llm:budget:{{{tenant}}}:{day}"

    async def reserve(self, tenant: str, day: str, tokens: int) -> bool:
        return int(await self._reserve(keys=[self._key(tenant, day)], args=[self._limit, tokens])) >= 0

    async def settle(self, tenant: str, day: str, reserved: int, actual: int) -> None:
        delta = actual - reserved
        if delta:
            await self._redis.incrby(self._key(tenant, day), delta)
```

```python
# app/llm/client.py
import asyncio
import hashlib
import hmac
import logging
import random
import time
from datetime import UTC, datetime

from opentelemetry import trace
from prometheus_client import Counter, Histogram

from app.llm.breaker import CircuitBreaker
from app.llm.budget import TenantTokenBudget
from app.llm.errors import FALLBACK_ELIGIBLE, RETRYABLE, FailureKind, LLMError
from app.llm.ports import ChatAdapter
from app.llm.registry import ModelSpec, PurposePolicy
from app.llm.types import LLMRequest, LLMResponse, Usage

log = logging.getLogger("llm.client")
tracer = trace.get_tracer("supportdesk.llm")

REQUESTS = Counter("llm_requests_total", "LLM logical requests", ["purpose", "outcome"])
ATTEMPTS = Counter("llm_attempts_total", "LLM provider attempts", ["provider", "model", "result"])
FALLBACKS = Counter("llm_fallbacks_total", "Fallbacks used", ["purpose", "to_model"])
TOKENS = Counter("llm_tokens_total", "Tokens", ["model", "type"])
COST = Counter("llm_cost_usd_total", "Cost in USD", ["model", "purpose"])
LATENCY = Histogram("llm_latency_seconds", "End-to-end latency", ["purpose"],
                    buckets=(0.25, 0.5, 1, 2, 4, 8, 16, 32, 64))

PROVIDER_HEALTH = {FailureKind.OVERLOADED, FailureKind.SERVER_ERROR, FailureKind.TIMEOUT, FailureKind.CONNECTION}


class LLMUnavailable(Exception):
    pass


class LLMClient:
    def __init__(self, adapters: dict[str, ChatAdapter], registry: dict[str, ModelSpec],
                 policies: dict[str, PurposePolicy], budget: TenantTokenBudget,
                 allowed_regions: set[str], log_salt: bytes) -> None:
        self._adapters, self._registry, self._policies = adapters, registry, policies
        self._budget, self._regions, self._salt = budget, allowed_regions, log_salt
        self._breakers = {key: CircuitBreaker() for key in registry}

    async def complete(self, req: LLMRequest, caller_deadline_s: float | None = None) -> LLMResponse:
        policy = self._policies[req.purpose]
        budget_s = min(policy.deadline_s, caller_deadline_s or policy.deadline_s)
        deadline = time.monotonic() + budget_s
        day = datetime.now(UTC).strftime("%Y%m%d")
        estimate = self._estimate_tokens(req, policy)
        started = time.monotonic()

        with tracer.start_as_current_span("llm.call") as span:
            span.set_attribute("llm.purpose", req.purpose)
            span.set_attribute("llm.prompt_hash", self._prompt_hash(req))    # correlate, don't reveal

            if not await self._budget.reserve(req.tenant_id, day, estimate):
                REQUESTS.labels(req.purpose, "budget_rejected").inc()
                return self._deterministic(policy, span, "budget_exhausted")

            candidates = [policy.primary, *policy.fallbacks]
            last_error: LLMError | None = None
            for index, key in enumerate(candidates):
                spec = self._registry[key]
                if not self._eligible(spec, req):
                    continue
                breaker = self._breakers[key]
                if not breaker.allow():
                    span.add_event("breaker_skip", {"model": key})
                    continue
                if index > 0:
                    FALLBACKS.labels(req.purpose, key).inc()
                    span.add_event("fallback", {"to": key, "reason": str(last_error.kind if last_error else "")})

                for attempt in range(1, policy.max_attempts_per_model + 1):
                    remaining = deadline - time.monotonic()
                    if remaining <= 0.2:
                        break
                    adapter = self._adapters[spec.provider]
                    try:
                        with tracer.start_as_current_span(f"chat {spec.model_id}") as attempt_span:
                            attempt_span.set_attribute("gen_ai.request.model", spec.model_id)
                            resp = await adapter.complete(spec.model_id, req, min(policy.timeout_s, remaining))
                            attempt_span.set_attribute("gen_ai.usage.input_tokens", resp.usage.input_tokens)
                            attempt_span.set_attribute("gen_ai.usage.output_tokens", resp.usage.output_tokens)
                    except LLMError as e:
                        last_error = e
                        ATTEMPTS.labels(spec.provider, key, str(e.kind)).inc()
                        if e.kind in PROVIDER_HEALTH:
                            breaker.record(False)
                        if e.kind not in RETRYABLE or attempt == policy.max_attempts_per_model:
                            break
                        await asyncio.sleep(min(self._backoff(attempt, e.retry_after_s),
                                                max(0.0, deadline - time.monotonic() - 0.2)))
                        continue

                    breaker.record(True)
                    ATTEMPTS.labels(spec.provider, key, "success").inc()
                    await self._settle(req, day, estimate, resp.usage)
                    self._account(req, spec, resp, started, attempt, index > 0)
                    return resp

                if last_error is not None and last_error.kind not in FALLBACK_ELIGIBLE:
                    break                                        # e.g. BAD_REQUEST: our bug; don't fan out

            await self._budget.settle(req.tenant_id, day, estimate, 0)   # release reservation
            REQUESTS.labels(req.purpose, f"failed_{last_error.kind if last_error else 'no_candidate'}").inc()
            if policy.deterministic_fallback is not None:
                return self._deterministic(policy, span, str(last_error.kind if last_error else "no_candidate"))
            raise LLMUnavailable(str(last_error) if last_error else "no eligible model")

    def _eligible(self, spec: ModelSpec, req: LLMRequest) -> bool:
        if spec.data_region not in self._regions:
            return False
        if req.json_schema is not None and not spec.supports_structured_output:
            return False
        return req.max_output_tokens <= spec.max_output_tokens

    @staticmethod
    def _backoff(attempt: int, retry_after: float | None) -> float:
        if retry_after is not None:
            return min(retry_after, 10.0)
        return random.uniform(0, min(8.0, 0.5 * 2 ** attempt))            # full jitter

    @staticmethod
    def _estimate_tokens(req: LLMRequest, policy: PurposePolicy) -> int:
        chars = len(req.system) + sum(len(m.text) for m in req.messages)
        return chars // 3 + min(req.max_output_tokens, policy.max_output_tokens)

    async def _settle(self, req: LLMRequest, day: str, reserved: int, usage: Usage) -> None:
        await self._budget.settle(req.tenant_id, day, reserved, usage.input_tokens + usage.output_tokens)

    def _account(self, req: LLMRequest, spec: ModelSpec, resp: LLMResponse,
                 started: float, attempts: int, fallback: bool) -> None:
        cost = (spec.price_in_per_mtok * resp.usage.input_tokens
                + spec.price_out_per_mtok * resp.usage.output_tokens) / 1_000_000
        TOKENS.labels(spec.key, "input").inc(resp.usage.input_tokens)
        TOKENS.labels(spec.key, "output").inc(resp.usage.output_tokens)
        COST.labels(spec.key, req.purpose).inc(float(cost))
        LATENCY.labels(req.purpose).observe(time.monotonic() - started)
        REQUESTS.labels(req.purpose, "fallback_success" if fallback else "success").inc()
        log.info("llm_call purpose=%s model=%s in=%d out=%d attempts=%d fallback=%s cost=%.6f stop=%s req_id=%s",
                 req.purpose, spec.key, resp.usage.input_tokens, resp.usage.output_tokens,
                 attempts, fallback, cost, resp.stop_reason, resp.provider_request_id)

    def _deterministic(self, policy: PurposePolicy, span, reason: str) -> LLMResponse:
        span.set_attribute("llm.degraded", True)
        span.add_event("deterministic_fallback", {"reason": reason})
        REQUESTS.labels(policy.purpose, "deterministic_fallback").inc()
        return LLMResponse(text=policy.deterministic_fallback or "", stop_reason="other",
                           usage=Usage(0, 0), model="deterministic", provider="none")

    def _prompt_hash(self, req: LLMRequest) -> str:
        material = (req.system + "\x1f" + "\x1f".join(m.text for m in req.messages)).encode()
        return hmac.new(self._salt, material, hashlib.sha256).hexdigest()[:16]
```

```python
import asyncio
import random

from app.llm.errors import FailureKind, LLMError


class FaultInjectingAdapter:
    def __init__(self, inner, error_rate: float = 0.0, kinds=(FailureKind.OVERLOADED,),
                 extra_latency_s: float = 0.0, seed: int | None = None) -> None:
        self._inner, self._error_rate, self._kinds = inner, error_rate, kinds
        self._latency, self._rng = extra_latency_s, random.Random(seed)
        self.provider = inner.provider

    async def complete(self, model, req, timeout_s):
        if self._latency:
            await asyncio.sleep(self._latency)
        if self._rng.random() < self._error_rate:
            raise LLMError(self._rng.choice(self._kinds), self.provider, model, retry_after_s=0.01)
        return await self._inner.complete(model, req, timeout_s)

    def stream(self, model, req, timeout_s):
        return self._inner.stream(model, req, timeout_s)
```

### 7. Comparative Analysis

| Comparison | Key difference | When | Trap |
|---|---|---|---|
| Protocol vs ABC for adapters | Structural vs nominal typing | Protocol for ports/fakes | Inheriting SDK classes into your domain |
| Thin wrapper vs full abstraction | Provider-shaped vs domain-shaped API | Domain-shaped with explicit capabilities | Lowest-common-denominator API hiding features |
| SDK retries vs client retries | Built-in vs centrally controlled | One layer only | Multiplied retries |
| Retry vs fallback | Same model again vs different model | Retry transient; fallback on sustained/overload | Unevaluated fallback models |
| Circuit breaker vs retries | Stop calling vs try again | Both: breaker gates retries | Breaker counting 400s as provider failures |
| Model fallback vs deterministic fallback | Another model vs fixed safe response | Model first if evaluated; deterministic last | Deterministic response pretending to be AI |
| Request caps vs tenant budgets | Per-call vs per-period | Both | Only global limits → one tenant starves others |
| Content logging vs metadata logging | Debuggable vs safe | Metadata default; restricted sampled capture | PII in central logs |
| Direct provider vs Bedrock adapter | Newest features vs AWS governance | Both behind the same port | Assuming identical behavior |
| Framework clients (LangChain chat models) vs own client | Ecosystem vs control | Own client for reliability core; frameworks at edges (Unit 33) | Hidden retries inside frameworks |

### 8. Failure Modes and Debugging

**Failure 1 — Retry storm during provider incident.**

- SYMPTOM: error rate 100%, request volume to provider ×9, own latency p99 = deadline.
- CAUSE: SDK retries (2) × client retries (3), no breaker, no retry budget.
- INVESTIGATE: `llm_attempts_total` vs `llm_requests_total`; traces show nested attempts.
- FIX: single retry layer, breaker, retry budget, fast fallback on overload.

**Failure 2 — Fallback succeeds but quality collapses.**

- SYMPTOM: support agents report worse drafts during an outage window; no errors.
- CAUSE: fallback model never evaluated for this purpose; prompts tuned for primary.
- FIX: evaluate fallbacks per purpose, alert on fallback rate, purpose-specific prompts per model if needed.

**Failure 3 — Budget drift.**

- SYMPTOM: tenant budget exceeded although reservations exist.
- CAUSE: settle not called on exceptions; estimates far below actual (huge outputs).
- FIX: settle/release in `finally`, conservative estimates, cap output tokens per purpose.

**Failure 4 — Breaker never opens.**

- CAUSE: `min_calls` too high for low traffic; failures classified as BAD_REQUEST.
- INVESTIGATE: breaker state gauge, failure-kind distribution.
- FIX: time-based window, correct classification.

**Failure 5 — Secrets in logs.**

- SYMPTOM: API key visible in an exception log.
- CAUSE: logging the settings object or full request config; provider error echoing headers.
- FIX: `SecretStr`, scrub exception messages, log only allowlisted fields.

**Failure 6 — Event loop stalls under Bedrock load.**

- CAUSE: sync boto3 call inside `async def` without a thread.
- INVESTIGATE: asyncio debug mode (`PYTHONASYNCIODEBUG=1` warns about slow callbacks), py-spy dump.
- FIX: `anyio.to_thread.run_sync` with a bounded thread limiter, or an async AWS client.

### 13. Interview Preparation

#### Quick Questions

**Q: Where should retries live in an LLM stack?**
*Strong answer:* In one layer, the client that knows the deadline, fallbacks and retry budget. Disable or avoid retries elsewhere to prevent multiplication.

**Q: What's a circuit breaker for?**
*Strong answer:* To stop calling an unhealthy dependency for a cool-down period, failing fast or falling back instead of piling up timeouts, then probe to recover.

**Q: What are the risks of fallback models?**
*Strong answer:* Behavior and quality drift, feature/schema differences, cost, latency, data residency, cache loss and silent degradation. Evaluate each fallback per purpose and alert on fallback rate.

#### Intermediate Questions

**Q: Design a provider abstraction.**
*Strong answer:* Domain request/response types, a small Protocol (`complete`, `stream`), adapters that translate requests, responses, stop reasons and errors into a taxonomy, a registry with explicit capabilities, and a client implementing reliability and accounting on top. No SDK types above adapters.
*Trap:* Wrapping one SDK and calling it an abstraction.

**Q: How do you enforce token budgets per tenant?**
*Strong answer:* Atomic reserve of an estimate in Redis (Lua) before the call, settle with actual usage after, release on failure, per-request output caps, alerts at thresholds, and degraded responses when exhausted.

**Q: What do you log for LLM calls?**
*Strong answer:* Metadata only: purpose, model, tokens, latency, stop reason, attempts, fallback, cost, request IDs, salted prompt hash. Content only via opt-in, redacted, sampled, restricted, short-retention capture.

#### Advanced Questions

**Q: Your primary model's provider is overloaded for 30 minutes. Walk through what your system does.**
*Strong answer:* First requests retry with jitter honoring `retry-after`. The overload failure rate opens the breaker, so requests go straight to the evaluated fallback (metric and alert fire). The retry budget prevents storms, and the deadline bounds latency. If the fallback is also down, deterministic degraded responses go out. Half-open probes detect recovery and traffic returns to primary. Dashboards show the fallback rate, cost delta and quality signals.

**Q: How do you test reliability logic without calling providers?**
*Strong answer:* Fakes and fault-injecting adapters with scripted outcomes, injectable clocks, property-based tests on bounds, recorded provider fixtures for adapter mapping, and staging chaos drills.

#### Coding Questions

1. Implement full-jitter backoff that respects `retry-after` and a remaining deadline.
2. Implement a count-based circuit breaker with an injectable clock.
3. Map Bedrock `ClientError` codes to a failure taxonomy.

#### Scenario Questions

**Q: Leadership asks to "just add OpenAI as a backup" tomorrow.**
*Strong answer:* Possible as an adapter, but enabling it requires evaluating quality per purpose, checking the data processing agreement and residency, structured output compatibility, cost and alerting. Propose a timeline: adapter and evals in days, then a canary.

### 14. Explain-It-at-Three-Levels

**Concept: Reliable LLM client**

- *30 seconds:* Features ask a provider-neutral client for a purpose. The client picks the model, enforces budgets and deadlines, retries only transient errors in one layer, trips breakers on unhealthy models, falls back to evaluated alternatives or a deterministic response, and records metrics without logging content.
- *2 minutes:* Taxonomy table, Protocol/adapters, registry/policies, breaker states, budget reserve/settle, observability.
- *Deep:* Internals of attempt loops and deadline math, breaker windows, retry budgets, streaming fallback constraints (only before first token), chaos testing, eval gates for fallbacks, and multi-process considerations.

**Concept: Fallback risk**

- *30 seconds:* A fallback keeps you available but can change quality, cost and compliance, so every fallback must be evaluated for the purpose, allowed by data rules and monitored.
- *2 minutes:* Kinds of fallback (model, platform, provider, deterministic) and their trade-offs.
- *Deep:* Prompt portability, structured output differences, caching effects, measuring degraded quality online, and deciding when to fail instead of falling back.

### 15. Knowledge Check

1. Why should `BAD_REQUEST` not trigger fallback to other models by default?
2. What's the difference between a per-attempt timeout and an overall deadline?
3. Why does the breaker count only provider-health failures?
4. Why reserve budget before the call instead of only recording after?
5. Why hash prompts with a secret salt instead of plain SHA-256?
6. *Code reading:* What happens in `LLMClient.complete` when the breaker for the primary is open?
7. *Code reading:* Why does `_eligible` check `data_region`?
8. *Code reading:* What's the purpose of `FaultInjectingAdapter`'s `seed`?
9. *Debugging:* `llm_attempts_total` is 9× `llm_requests_total` during an incident. Diagnosis?
10. *Debugging:* Logs show `cost=0` for many calls. Likely causes?
11. *Design:* Should streaming responses fall back mid-stream?
12. *Design:* In-process or Redis-shared circuit breakers?

#### Knowledge Check Answers

1. It usually indicates our request is invalid (a bug or unsupported parameter). Sending it to more models wastes calls and can hide the bug. Exception: a model-specific unsupported parameter where the fallback model supports the request.
2. The per-attempt timeout bounds one provider call. The deadline bounds the whole logical operation including retries and fallbacks, protecting the caller's SLO.
3. Client errors and refusals don't indicate provider health. Counting them would open the breaker for the wrong reasons.
4. To prevent concurrent requests from collectively exceeding the budget. Recording only afterwards allows overspending under concurrency.
5. Plain hashes of short or guessable prompts can be brute-forced or looked up. A secret-keyed HMAC prevents reversing while still allowing correlation.
6. It's skipped (event `breaker_skip`), and the client moves to the next eligible fallback without waiting on timeouts.
7. Compliance: only models in allowed regions may process this tenant's data, even during failover.
8. Reproducible fault sequences in tests, so failures are deterministic.
9. Retries are multiplying (SDK + client), possibly with no breaker or retry budget. Check client configuration (`max_retries`) and traces.
10. Model key missing from the price table (default zero), deterministic fallbacks counted as calls, or usage parsing failing for a provider.
11. Generally no. After the first token is sent, switching models would produce an incoherent response. Fall back only before the first token, and otherwise send an error event and let the client retry.
12. In-process is usually sufficient and avoids a hot-path dependency. Use shared state for very low per-process traffic or when coordinated failover matters.

### 16. Common Interview Traps

- **"Our abstraction supports any provider."** Usually it's one provider's shape. Expose capabilities explicitly.
- **"Retries make it reliable."** Uncontrolled retries cause storms. Use one layer, budgets and breakers.
- **"Fallback models are a free win."** They change behavior, cost and compliance.
- **"Log prompts for debugging."** That's a privacy liability. Use metadata plus restricted capture.
- **"Circuit breakers replace timeouts."** You need both.
- **"Budgets can be checked after the call."** Concurrency defeats post-hoc checks.
- **"Fallback mid-stream."** It produces incoherent outputs.

### 17. Cheat Sheet

- **Layers:** feature → `LLMClient` (policy, budget, deadline, retries, breaker, fallback, metrics, safe logs) → `ChatAdapter` Protocol → provider adapters (translate errors to `LLMError(kind)`).
- **Kinds:** RATE_LIMITED, OVERLOADED, SERVER_ERROR, TIMEOUT, CONNECTION (retryable); BAD_REQUEST, AUTH, NOT_FOUND, CONTENT_FILTERED (not retryable; some fallback-eligible).
- **Backoff:** full jitter `uniform(0, min(cap, base·2^n))`; honor retry-after; cap by remaining deadline; retry budget.
- **Breaker:** CLOSED → OPEN (rate ≥ threshold, ≥ min calls) → HALF_OPEN (cool-down) → probe; count provider-health failures only.
- **Fallback:** evaluated per purpose; region/capability eligibility; alert on rate; deterministic last resort; never mid-stream.
- **Budget:** reserve (Lua, atomic) → call → settle actual → release on failure; per-request output caps.
- **Logging:** metadata, HMAC prompt hash, provider request ID; no content; `SecretStr`; restricted debug capture.
- **Metrics:** requests by outcome, attempts by result, fallbacks, tokens, cost, latency, breaker state, budget rejections.
