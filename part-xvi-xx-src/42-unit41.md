## Unit 41 — Spring Coding Interviews

### 1. Learning Objectives

By the end of this unit you will be able to:

1. **Implement**, within 60 minutes, a Customer CRUD API with Spring Boot 4, PostgreSQL (Flyway), Bean Validation, centralized exception handling with Problem Details, and tests.
2. **Extend** it within a further 30 minutes (90 total) with JWT-secured endpoints (OAuth2 resource server), pagination and filtering.
3. **Extend** it within a further 30 minutes (120 total) with Kafka events (with a reliable publishing story), Redis caching, and Testcontainers-based integration tests for PostgreSQL, Kafka and Redis.
4. **Narrate** design choices while coding: DTO/domain separation, transaction boundaries, status codes, error format, security rules, cache invalidation, event reliability, and test strategy.
5. **Prioritize** under time pressure: deliver a working vertical slice first, then add depth; know what to say about what you didn't build.
6. **Debug** common setup failures quickly: datasource/Flyway errors, 401/403 misconfig, Jackson serialization of entities, cache serialization, Testcontainers wiring.

### 2. Prerequisite Knowledge

- Spring Boot 4.1 project setup (start.spring.io), Maven or Gradle, `application.yml`.
- Spring MVC controllers, `@Valid`, `ProblemDetail`/`@RestControllerAdvice`.
- Spring Data JPA (entities, repositories, `Pageable`, `Specification`), or `JdbcClient`.
- Spring Security 7 lambda DSL; OAuth2 resource server (JWT).
- Spring Kafka (`KafkaTemplate`, `@KafkaListener`), Spring Data Redis / Spring Cache.
- Testcontainers 2.x with `@ServiceConnection`; JUnit Jupiter; MockMvc/`MockMvcTester`.

**[Version-dependent] Boot 4 testing notes.** Boot 4 splits test auto-configuration into per-technology modules. `@WebMvcTest` and `@AutoConfigureMockMvc` live in `spring-boot-webmvc-test` (package `org.springframework.boot.webmvc.test.autoconfigure`), and `@DataJpaTest` in `spring-boot-data-jpa-test` (package `org.springframework.boot.data.jpa.test.autoconfigure`). Starters such as `spring-boot-starter-webmvc-test` pull them in. `@MockBean` was removed in favor of `@MockitoBean` (Spring Framework). If your IDE can't find an annotation, check the module, not your memory of Boot 3 packages.

**Prepare before the interview (allowed in most take-home/live formats):** a pre-generated project skeleton with dependencies, a `compose.yaml` for PostgreSQL, a test base class for Testcontainers, and your IDE live templates. Ask the interviewer at the start what's allowed.

### 3. Mental Model

A timed Spring build is **a vertical slice delivered in increments, with narration as a deliverable**:

```
Minute 0 ──────────────── 60 ─────────────── 90 ──────────────── 120
[Clarify 5][Skeleton 5][Domain+DB 10][API 15][Errors 5][Tests 15][Buffer 5]
                                     [JWT 12][Paging+Filter 12][Tests 6]
                                                         [Kafka 12][Redis 8][TC tests 10]
Always: green build → commit → narrate → next increment
```

Three rules:

1. **Working beats complete.** Have something runnable by minute 25. Every increment ends green.
2. **Narrate decisions, not keystrokes.** "I'm returning 201 with a Location header because…", not "now I'm typing the annotation".
3. **Make trade-offs explicit.** "Given the time, I'm publishing the event after commit with `@TransactionalEventListener`. In production I'd use an outbox, because this can lose events if the process crashes between commit and send."

### 4. Comprehensive Theory

#### 4.1 Clarifying the Spec (first 5 minutes)

Ask and write down:

- **Fields and constraints:** `Customer {id, firstName, lastName, email (unique), phone?, status (ACTIVE/INACTIVE), createdAt, updatedAt}`. Is email case-insensitive? Max lengths?
- **Operations:** create, get, update (PUT full or PATCH partial?), delete (hard or soft?), list.
- **Errors:** duplicate email → 409? validation → 400 with field errors?
- **Non-functional:** expected size (pagination needed?), concurrency (optimistic locking?), auth (later stage).
- **Deliverables:** tests expected? Docker? README?

Write the decisions as comments in a `NOTES.md` or at the top of the controller. It shows structure and gives you a checklist.

#### 4.2 Architecture for the Build

```
api/        CustomerController, dto/{CreateCustomerRequest, UpdateCustomerRequest, CustomerResponse, PageResponse}
            ApiExceptionHandler (ProblemDetail)
domain/     Customer (entity), CustomerStatus, CustomerNotFoundException, DuplicateEmailException
service/    CustomerService (transactions, business rules, mapping)
repo/       CustomerRepository (Spring Data JPA, Specifications)
config/     SecurityConfig, CacheConfig, KafkaConfig
events/     CustomerEvent, CustomerEventPublisher (+ outbox at 120 min if time)
resources/  application.yml, db/migration/V1__customers.sql
```

**Why these boundaries.** DTO records at the edge (validation, no entity leakage, stable contract). Service owns transactions and rules. Repository is the data access layer. Exceptions are domain-specific and mapped centrally. This is enough structure to look professional without ceremony (no interfaces for single implementations, no mapper libraries needed).

#### 4.3 Validation and Errors

- Request DTOs as records with Jakarta constraints. `@Valid @RequestBody`.
- Spring MVC throws `MethodArgumentNotValidException` for body validation. For method-parameter validation (`@RequestParam @Min`), Spring Framework 6.1+ applies built-in method validation (`HandlerMethodValidationException`).
- Return **RFC 9457 Problem Details** (`ProblemDetail`) with an `errors` extension listing `{field, message}`. Enable `spring.mvc.problemdetails.enabled=true` for framework exceptions, and add an advice for your own.
- Status codes: 400 validation, 404 not found, 409 duplicate/optimistic lock conflict, 401/403 security, 500 unexpected (no stack traces in the body).
- Duplicate email: check-then-insert races, so **rely on the unique constraint** and translate `DataIntegrityViolationException` (optionally pre-check for a nicer message, but the constraint is the source of truth).

#### 4.4 Persistence Choices

- Flyway migration with explicit SQL (shows you know the schema): `citext` or a lower-case unique index for case-insensitive email.
- JPA entity with `@Version` (optimistic locking → 409 on concurrent update).
- `spring.jpa.open-in-view=false`, `ddl-auto=validate` (Flyway owns the schema).
- Timestamps: `@CreationTimestamp`/`@UpdateTimestamp` (Hibernate) or set in service with an injected `Clock`.

#### 4.5 JWT, Pagination, Filtering (90-minute stage)

**JWT.** In an interview, there are two realistic setups:

1. **Resource server against an issuer** (Keycloak/Auth0/Cognito): `spring.security.oauth2.resourceserver.jwt.issuer-uri`. This is the most realistic, but needs an IdP running.
2. **Self-contained HMAC for the exercise:** a `JwtDecoder` with a secret key, plus a dev-only token endpoint using `JwtEncoder`. State clearly that production uses an IdP with asymmetric keys (JWKS), and that you'd never ship a homemade login.

Authorization: `customers:read` for GETs, `customers:write` for mutations, using `SCOPE_` authorities. Stateless sessions. CSRF disabled for a bearer-token API, and say why.

**Pagination.** `Pageable` with `page`, `size` (cap the max, for example 100) and `sort` (allowlist sortable fields to avoid errors and injection-like abuse of arbitrary properties). Return a stable DTO (`PageResponse<T>`: content, page, size, totalElements, totalPages) rather than serializing Spring's `PageImpl` directly. Spring Data warns about `PageImpl` JSON stability and offers `PagedModel`/`VIA_DTO` serialization mode. Mention keyset pagination for large tables.

**Filtering.** Query params (`status`, `email` contains, `createdAfter`). Implement with JPA `Specification` (composable, type-safe) or `JdbcClient` with a carefully built WHERE clause (parameters only, never string-concatenate values). Add indexes that match the filters.

#### 4.6 Kafka, Redis, Testcontainers (120-minute stage)

**Kafka events.** Publish `CustomerCreated`/`CustomerUpdated`/`CustomerDeleted` with key = customer ID (per-customer ordering). Reliability options, in order of time cost:

| Option | Reliability | Time |
|---|---|---|
| `kafkaTemplate.send` inside the transaction | Event may be sent even if the tx rolls back (phantom event) | fastest, wrong |
| `@TransactionalEventListener(phase = AFTER_COMMIT)` → send | No phantom events; can **lose** events on crash after commit | 5 min |
| **Transactional outbox** (table + poller) | No loss, no phantom; at-least-once | 15–20 min |

In an interview, implement option 2 if time is tight *and say* option 3 is the production answer. If time allows, implement the outbox with a `@Scheduled` poller.

**Redis cache.** `@Cacheable("customers", key = "#id")` on `getById`, with `@CacheEvict` on update and delete. Configure `RedisCacheManager` with TTL and JSON serialization (cache DTOs, not entities). Discuss stampede protection (`sync = true`), what not to cache (list endpoints with many filter combinations), and that the cache must not change authorization semantics (the check happens before the cached method, or the cached data is not user-specific).

**Testcontainers.** `@ServiceConnection` on `PostgreSQLContainer`, `KafkaContainer` (apache/kafka image) and a generic Redis container. Use a shared base class with static containers (started once per JVM) to keep tests fast. Test: create → event appears on topic, get → second call hits cache (verify via a repository spy or cache stats), update → cache evicted.

#### 4.7 Narrating While Coding

Phrases that signal seniority (use your own words):

- "I'll start with the migration because the schema is the contract with the database."
- "I'm using a record for the request DTO so validation lives at the edge and the entity never leaks."
- "The unique index is the source of truth for duplicate emails. A pre-check alone would race."
- "`@Transactional` goes on the service, not the controller. One business operation, one transaction."
- "I'm capping page size at 100 to protect the database."
- "I'll write a slice test for the controller's error mapping and an integration test against real PostgreSQL. H2 would hide dialect issues like `citext`."
- "Given 10 minutes left, I'll skip PATCH and explain how I'd do it with JSON Merge Patch."

### 5. Internal Mechanics — What Your 60 Lines Actually Trigger

```
POST /api/customers {json}
→ Security filter chain (90-min stage: BearerTokenAuthenticationFilter → JwtDecoder → JwtAuthenticationToken)
→ DispatcherServlet → RequestMappingHandlerAdapter
→ RequestResponseBodyMethodProcessor: Jackson 3 reads JSON → CreateCustomerRequest (record canonical ctor)
→ @Valid → Validator → MethodArgumentNotValidException (→ advice → 400 ProblemDetail)
→ CustomerController.create → CustomerService (CGLIB proxy) → TransactionInterceptor begins tx
→ repository.save → EntityManager.persist → INSERT at flush (before commit)
→ unique violation → ConstraintViolationException (Hibernate) → translated to DataIntegrityViolationException
   by Spring's exception translation (repository proxy / at commit) → advice → 409
→ commit → AFTER_COMMIT listeners (event publish) → response 201 + Location
→ @Cacheable on GET: CacheInterceptor → RedisCache.get(key) → hit: return without calling method
```

Note where the duplicate-key error surfaces. With `save()` and generated IDs (`IDENTITY`), Hibernate inserts immediately. With sequence IDs, the insert happens at flush/commit, so the exception may surface at commit, outside your `try/catch` in the service. Handle `DataIntegrityViolationException` in the advice, or call `saveAndFlush` where you need the error inside the method.

```java
package com.example.customers.domain;

import jakarta.persistence.*;
import java.time.Instant;

@Entity
@Table(name = "customer")
public class Customer {

    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    @Column(nullable = false) private String firstName;
    @Column(nullable = false) private String lastName;
    @Column(nullable = false, unique = true, columnDefinition = "citext") private String email;
    private String phone;
    @Enumerated(EnumType.STRING) @Column(nullable = false) private CustomerStatus status = CustomerStatus.ACTIVE;
    @Column(nullable = false) private Instant createdAt;
    @Column(nullable = false) private Instant updatedAt;
    @Version private long version;

    protected Customer() {}

    public Customer(String firstName, String lastName, String email, String phone, Instant now) {
        this.firstName = firstName;
        this.lastName = lastName;
        this.email = email;
        this.phone = phone;
        this.createdAt = now;
        this.updatedAt = now;
    }

    public void update(String firstName, String lastName, String email, String phone,
                       CustomerStatus status, Instant now) {
        this.firstName = firstName;
        this.lastName = lastName;
        this.email = email;
        this.phone = phone;
        this.status = status;
        this.updatedAt = now;
    }

    public Long getId() { return id; }
    public String getFirstName() { return firstName; }
    public String getLastName() { return lastName; }
    public String getEmail() { return email; }
    public String getPhone() { return phone; }
    public CustomerStatus getStatus() { return status; }
    public Instant getCreatedAt() { return createdAt; }
    public Instant getUpdatedAt() { return updatedAt; }
    public long getVersion() { return version; }
}
```

```java
package com.example.customers.api.dto;

import com.example.customers.domain.Customer;
import com.example.customers.domain.CustomerStatus;
import jakarta.validation.constraints.*;
import java.time.Instant;

public record CreateCustomerRequest(
        @NotBlank @Size(max = 100) String firstName,
        @NotBlank @Size(max = 100) String lastName,
        @NotBlank @Email @Size(max = 254) String email,
        @Pattern(regexp = "\\+?[0-9 ()-]{7,30}") String phone) {}

public record UpdateCustomerRequest(
        @NotBlank @Size(max = 100) String firstName,
        @NotBlank @Size(max = 100) String lastName,
        @NotBlank @Email @Size(max = 254) String email,
        @Pattern(regexp = "\\+?[0-9 ()-]{7,30}") String phone,
        @NotNull CustomerStatus status,
        @NotNull Long version) {}             // optimistic concurrency from the client

public record CustomerResponse(Long id, String firstName, String lastName, String email, String phone,
                               CustomerStatus status, Instant createdAt, Instant updatedAt, long version) {
    public static CustomerResponse from(Customer c) {
        return new CustomerResponse(c.getId(), c.getFirstName(), c.getLastName(), c.getEmail(), c.getPhone(),
                                    c.getStatus(), c.getCreatedAt(), c.getUpdatedAt(), c.getVersion());
    }
}
```

```java
package com.example.customers.service;

import com.example.customers.api.dto.*;
import com.example.customers.domain.*;
import com.example.customers.repo.CustomerRepository;
import org.springframework.orm.ObjectOptimisticLockingFailureException;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.time.Clock;

@Service
@Transactional(readOnly = true)
public class CustomerService {

    private final CustomerRepository repo;
    private final Clock clock;

    public CustomerService(CustomerRepository repo, Clock clock) {
        this.repo = repo;
        this.clock = clock;
    }

    @Transactional
    public CustomerResponse create(CreateCustomerRequest r) {
        var saved = repo.save(new Customer(r.firstName(), r.lastName(), r.email(), r.phone(), clock.instant()));
        return CustomerResponse.from(saved);
    }

    public CustomerResponse get(long id) {
        return CustomerResponse.from(find(id));
    }

    @Transactional
    public CustomerResponse update(long id, UpdateCustomerRequest r) {
        Customer c = find(id);
        if (c.getVersion() != r.version()) {
            throw new ObjectOptimisticLockingFailureException(Customer.class, id);
        }
        c.update(r.firstName(), r.lastName(), r.email(), r.phone(), r.status(), clock.instant());
        return CustomerResponse.from(repo.saveAndFlush(c));   // flush: surface constraint errors here
    }

    @Transactional
    public void delete(long id) {
        repo.delete(find(id));
    }

    private Customer find(long id) {
        return repo.findById(id).orElseThrow(() -> new CustomerNotFoundException(id));
    }
}
```

```java
package com.example.customers.api;

import com.example.customers.api.dto.*;
import com.example.customers.service.CustomerService;
import jakarta.validation.Valid;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;
import org.springframework.web.servlet.support.ServletUriComponentsBuilder;

@RestController
@RequestMapping("/api/customers")
class CustomerController {

    private final CustomerService service;

    CustomerController(CustomerService service) { this.service = service; }

    @PostMapping
    ResponseEntity<CustomerResponse> create(@Valid @RequestBody CreateCustomerRequest request) {
        CustomerResponse created = service.create(request);
        var location = ServletUriComponentsBuilder.fromCurrentRequest()
            .path("/{id}").buildAndExpand(created.id()).toUri();
        return ResponseEntity.created(location).body(created);
    }

    @GetMapping("/{id}")
    CustomerResponse get(@PathVariable long id) { return service.get(id); }

    @PutMapping("/{id}")
    CustomerResponse update(@PathVariable long id, @Valid @RequestBody UpdateCustomerRequest request) {
        return service.update(id, request);
    }

    @DeleteMapping("/{id}")
    ResponseEntity<Void> delete(@PathVariable long id) {
        service.delete(id);
        return ResponseEntity.noContent().build();
    }
}
```

```java
package com.example.customers.api;

import com.example.customers.domain.CustomerNotFoundException;
import org.springframework.dao.DataIntegrityViolationException;
import org.springframework.http.HttpHeaders;
import org.springframework.http.HttpStatus;
import org.springframework.http.HttpStatusCode;
import org.springframework.http.ProblemDetail;
import org.springframework.http.ResponseEntity;
import org.springframework.orm.ObjectOptimisticLockingFailureException;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;
import org.springframework.web.context.request.WebRequest;
import org.springframework.web.servlet.mvc.method.annotation.ResponseEntityExceptionHandler;

import java.net.URI;
import java.util.List;
import java.util.Map;

@RestControllerAdvice
class ApiExceptionHandler extends ResponseEntityExceptionHandler {

    @ExceptionHandler(CustomerNotFoundException.class)
    ProblemDetail notFound(CustomerNotFoundException e) {
        ProblemDetail pd = ProblemDetail.forStatusAndDetail(HttpStatus.NOT_FOUND, e.getMessage());
        pd.setType(URI.create("https://api.example.com/problems/customer-not-found"));
        return pd;
    }

    @ExceptionHandler(DataIntegrityViolationException.class)
    ProblemDetail conflict(DataIntegrityViolationException e) {
        // Don't echo the DB message (leaks schema). Map known constraints to friendly messages.
        ProblemDetail pd = ProblemDetail.forStatusAndDetail(HttpStatus.CONFLICT, "Email already in use");
        pd.setType(URI.create("https://api.example.com/problems/duplicate-email"));
        return pd;
    }

    @ExceptionHandler(ObjectOptimisticLockingFailureException.class)
    ProblemDetail stale(ObjectOptimisticLockingFailureException e) {
        return ProblemDetail.forStatusAndDetail(HttpStatus.CONFLICT, "Customer was modified; reload and retry");
    }

    @Override
    protected ResponseEntity<Object> handleMethodArgumentNotValid(MethodArgumentNotValidException ex,
            HttpHeaders headers, HttpStatusCode status, WebRequest request) {
        ProblemDetail pd = ex.getBody();               // already a 400 ProblemDetail
        List<Map<String, String>> errors = ex.getBindingResult().getFieldErrors().stream()
            .map(fe -> Map.of("field", fe.getField(), "message", String.valueOf(fe.getDefaultMessage())))
            .toList();
        pd.setProperty("errors", errors);
        return ResponseEntity.badRequest().body(pd);
    }
}
```

```java
package com.example.customers.config;

import org.springframework.beans.factory.annotation.Value;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.http.HttpMethod;
import org.springframework.security.config.Customizer;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.config.annotation.web.configurers.AbstractHttpConfigurer;
import org.springframework.security.config.http.SessionCreationPolicy;
import org.springframework.security.oauth2.jose.jws.MacAlgorithm;
import org.springframework.security.oauth2.jwt.JwtDecoder;
import org.springframework.security.oauth2.jwt.NimbusJwtDecoder;
import org.springframework.security.web.SecurityFilterChain;

import javax.crypto.spec.SecretKeySpec;
import java.nio.charset.StandardCharsets;

@Configuration
class SecurityConfig {

    @Bean
    SecurityFilterChain api(HttpSecurity http) throws Exception {
        http
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/actuator/health/**").permitAll()
                .requestMatchers(HttpMethod.GET, "/api/customers/**").hasAuthority("SCOPE_customers:read")
                .requestMatchers("/api/customers/**").hasAuthority("SCOPE_customers:write")
                .anyRequest().authenticated())
            .oauth2ResourceServer(rs -> rs.jwt(Customizer.withDefaults()))
            .sessionManagement(s -> s.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .csrf(AbstractHttpConfigurer::disable);   // bearer tokens in headers; no cookies
        return http.build();
    }

    /** Interview-only HMAC decoder. Production: spring.security.oauth2.resourceserver.jwt.issuer-uri (JWKS). */
    @Bean
    JwtDecoder jwtDecoder(@Value("${app.jwt.secret}") String secret) {
        var key = new SecretKeySpec(secret.getBytes(StandardCharsets.UTF_8), "HmacSHA256");
        return NimbusJwtDecoder.withSecretKey(key).macAlgorithm(MacAlgorithm.HS256).build();
    }
}
```

Spring Security's default JWT converter maps the `scope`/`scp` claim to `SCOPE_` authorities. Add an issuer/audience validator (`JwtValidators.createDefaultWithIssuer(...)` plus a custom audience check) and say so even if you skip it for time.

```java
package com.example.customers.repo;

import com.example.customers.domain.Customer;
import com.example.customers.domain.CustomerStatus;
import org.springframework.data.jpa.domain.Specification;

import java.time.Instant;

public final class CustomerSpecs {
    private CustomerSpecs() {}

    public static Specification<Customer> hasStatus(CustomerStatus status) {
        return (root, q, cb) -> status == null ? null : cb.equal(root.get("status"), status);
    }

    public static Specification<Customer> emailContains(String fragment) {
        return (root, q, cb) -> fragment == null || fragment.isBlank() ? null
            : cb.like(cb.lower(root.get("email")), "%" + escapeLike(fragment.toLowerCase()) + "%", '\\');
    }

    public static Specification<Customer> createdAfter(Instant after) {
        return (root, q, cb) -> after == null ? null : cb.greaterThan(root.get("createdAt"), after);
    }

    private static String escapeLike(String s) {
        return s.replace("\\", "\\\\").replace("%", "\\%").replace("_", "\\_");
    }
}
```

```java
package com.example.customers.events;

import org.springframework.kafka.core.KafkaTemplate;
import org.springframework.stereotype.Component;
import org.springframework.transaction.event.TransactionPhase;
import org.springframework.transaction.event.TransactionalEventListener;

@Component
class CustomerEventPublisher {

    static final String TOPIC = "customers.events";
    private final KafkaTemplate<String, CustomerEvent> kafka;

    CustomerEventPublisher(KafkaTemplate<String, CustomerEvent> kafka) { this.kafka = kafka; }

    // Fires only if the DB transaction committed. Can still lose the event if the process dies right now.
    // Production: write to an outbox table in the same transaction; a relay publishes (Unit 38).
    @TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
    void on(CustomerEvent event) {
        kafka.send(TOPIC, String.valueOf(event.customerId()), event);
    }
}
```

### 7. Comparative Analysis

| Decision | Option A | Option B | What to say |
|---|---|---|---|
| Data access | Spring Data JPA | `JdbcClient` | JPA for CRUD speed in interviews; JdbcClient when SQL control or bulk ops matter |
| Update semantics | PUT (full replace) | PATCH (JSON Merge Patch) | PUT is simpler under time pressure; PATCH needs null semantics |
| Delete | Hard delete | Soft delete (`deleted_at`) | Ask; soft delete affects unique constraints (partial unique index) and every query |
| Duplicate check | Pre-check only | Unique constraint + translation | Constraint is source of truth; pre-check optional for UX |
| Errors | Custom JSON | `ProblemDetail` (RFC 9457) | Standard format, built into Spring |
| Pagination | Offset (`Pageable`) | Keyset | Offset for small/medium tables and UIs with page numbers; keyset for large/infinite scroll |
| Filtering | `Specification` | Query methods / `@Query` | Specifications compose optional filters cleanly |
| JWT | HMAC (interview) | IdP + JWKS (prod) | Explicitly flag the difference |
| Events | After-commit listener | Outbox | Listener is fast to build; outbox is the reliable answer |
| Cache | `@Cacheable` Redis | Caffeine local | Redis for multi-instance consistency; local for hot read-only data |
| Tests | `@WebMvcTest` slices | `@SpringBootTest` + Testcontainers | Both: slices for speed, ITs for real wiring |
| DB in tests | Testcontainers PostgreSQL | H2 | H2 hides dialect issues (citext, jsonb, constraints) |

### 8. Failure Modes and Debugging

**Failure 1 — App won't start: `Schema-validation: missing column`.**
- CAUSE: `ddl-auto=validate` and entity/migration mismatch (for example `columnDefinition` or naming).
- INVESTIGATE: Read the full message (table/column), check the Flyway history table (`flyway_schema_history`).
- FIX: Align the migration/entity. Never switch to `update` to "fix" it.

**Failure 2 — 401 for every request with a valid-looking token.**
- CAUSE: Wrong secret/algorithm, missing `scope` claim, expired token, issuer validator mismatch, clock skew.
- INVESTIGATE: `logging.level.org.springframework.security=DEBUG`; decode the token (header alg, claims); check `WWW-Authenticate` response header (it states `invalid_token` with a description).
- FIX: Align the configuration. 403 instead of 401 means authenticated but missing authority, so check the `SCOPE_` mapping.

**Failure 3 — `HttpMessageNotWritableException` / infinite recursion.**
- CAUSE: Returning entities with bidirectional relations or lazy proxies.
- FIX: Return DTOs.

**Failure 4 — Duplicate email returns 500.**
- CAUSE: Exception surfaces at commit (after the service method), not caught by a service try/catch, and no advice mapping.
- FIX: Advice for `DataIntegrityViolationException`, or `saveAndFlush`.

**Failure 5 — Cache returns `ClassCastException`/`LinkedHashMap`.**
- CAUSE: The JSON serializer lacks type info, so cached values deserialize to maps.
- FIX: A typed serializer per cache, or a correctly configured generic serializer.

**Failure 6 — Testcontainers tests hang or fail in CI.**
- CAUSE: No Docker in CI, wrong image architecture, Kafka listener started before container, or a port binding assumption.
- FIX: Use `@ServiceConnection` (don't hard-code ports), singleton containers, and the CI Docker service. Check `docker info` in CI logs.

**Failure 7 — Events published for rolled-back transactions.**
- CAUSE: `kafkaTemplate.send` called directly inside `@Transactional` methods.
- FIX: After-commit listener or outbox.

**Debugging habit to show:** read the *whole* stack trace from the bottom "Caused by", reproduce with one curl, add one targeted log or breakpoint, fix and re-run the test.

### 12. Engineering Scenarios

### 13. Interview Preparation

#### Quick Questions

**Q: Why DTOs instead of returning entities?**
*Strong answer:* Contract stability, no lazy-loading/serialization issues, no over-exposure of fields, validation at the edge, and decoupled persistence model.

**Q: Where does `@Transactional` belong?**
*Strong answer:* On service methods representing one business operation. Read-only for queries. Not on controllers (too broad) or repositories (too narrow for multi-step operations).

**Q: 401 vs 403?**
*Strong answer:* 401: not authenticated (missing/invalid token). 403: authenticated but lacks permission.

#### Intermediate Questions

**Q: How do you guarantee unique emails under concurrency?**
*Strong answer:* A unique (case-insensitive) constraint in the database, translated to 409. Pre-checks alone race.

**Q: How do you publish an event only when the DB transaction commits, and never lose it?**
*Strong answer:* After-commit listener avoids phantom events but can lose them. A transactional outbox (same-transaction insert + relay) gives at-least-once without loss, with idempotent consumers.

**Q: How do you design pagination for an API?**
*Strong answer:* Cap the size, allowlist sort fields, return a stable page DTO, use indexes matching sort and filters, and use keyset pagination for large or changing datasets.

#### Advanced Questions

**Q: Your `@Cacheable` read and `@CacheEvict` write race. Explain and fix.**
*Strong answer:* Eviction happens at method return, before commit. A concurrent read between eviction and commit reloads the old value and caches it. Fix by evicting after commit (transaction synchronization or an after-commit listener), using versioned cache entries, or accepting a short TTL. Also check proxy ordering (`@Order` on advisors) if both annotations are on the same method.

**Q: How would you make POST /customers idempotent?**
*Strong answer:* `Idempotency-Key` header + idempotency table (Unit 38), or a natural key (email uniqueness already makes duplicate creates fail with 409, but clients may prefer replaying the original 201).

#### Coding Questions

1. Write the `ProblemDetail` advice for validation errors with a field list.
2. Write a `Specification` for an optional status filter and an optional date range.
3. Write a `@WebMvcTest` asserting 403 for a write without the write scope.
4. Write an after-commit event publisher and explain its failure mode.

#### Scenario Questions

**Q: At minute 50 your app fails to start because of a Flyway error you don't understand. What do you do?**
*Strong answer:* Read the root cause aloud, check the migration SQL and the `flyway_schema_history` state (a failed migration leaves a failed entry; clean the dev DB or repair), fix, and restart. If blocked > 5 minutes, simplify (temporarily drop the problematic feature such as `citext` → lower-case unique index) and note it.

### 15. Knowledge Check

1. Why does `ddl-auto=validate` pair well with Flyway?
2. What does `@Version` give you, and what status code maps to a conflict?
3. Why cap page size and allowlist sort fields?
4. Why disable CSRF for a stateless bearer-token API (and when must you not)?
5. Why can `@TransactionalEventListener(AFTER_COMMIT)` lose events?
6. *Code reading:* Why does the advice not echo the database error message?
7. *Code reading:* Why does `update` call `saveAndFlush`?
8. *Code reading:* What does a `null` predicate in a `Specification` do?
9. *Debugging:* Valid tokens get 403 on GET. What do you check first?
10. *Debugging:* Duplicate email returns 500. Why might your handler not run?
11. *Design:* After-commit listener or outbox in a 120-minute interview?
12. *Design:* Should list endpoints be cached in Redis?

#### Knowledge Check Answers

1. Flyway owns schema changes explicitly and versioned. Validation fails fast at startup if entities and schema diverge, instead of silently altering the schema.
2. Optimistic locking: concurrent updates detect conflicts (version mismatch) → `ObjectOptimisticLockingFailureException` → 409 Conflict (or 412 with `If-Match`).
3. To protect the database from huge scans/sorts and to prevent errors or abuse from sorting by arbitrary (possibly unindexed or sensitive) properties.
4. CSRF exploits browsers attaching cookies automatically. Bearer tokens in headers aren't attached automatically. You must keep CSRF protection if you use cookie-based auth (including tokens in cookies).
5. The publish happens in memory after commit. A crash, Kafka outage, or send failure after commit loses the event, with no durable record to retry from.
6. It would leak schema details (table/constraint names, values) to clients.
7. To force the flush inside the method so constraint violations surface there (and are translated within the transaction scope), not at commit after the method returns.
8. It's ignored, so optional filters simply drop out of the combined predicate.
9. Authorities: does the token have the `scope`/`scp` claim with `customers:read`, and does the mapping produce `SCOPE_customers:read`? Check the matcher order in the security config.
10. The exception surfaced at commit outside the code path you expected, or your handler handles a different exception type (Hibernate's vs Spring's translated one), or a broader handler matched first.
11. Implement after-commit if time is short, and explain the outbox as the production answer. Implement the outbox if time allows. Either way, state the trade-off.
12. Rarely. Many filter/page combinations give low hit rates and invalidation is hard. Cache single-entity reads; consider short TTLs for a few hot list queries.

- **Cache:** `@Cacheable(sync = true)`, `@CacheEvict`, typed JSON serializer, eviction-before-commit race.
- **Tests:** `@WebMvcTest` + `MockMvcTester` + `@MockitoBean`; `jwt()` post-processor; Testcontainers singleton base with `@ServiceConnection`.
- **Boot 4 gotchas:** test annotations moved to per-tech modules; `@MockBean` removed; Jackson 3 (`tools.jackson.*`); Kafka/Redis Jackson 3 serializers.
