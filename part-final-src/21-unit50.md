### 3. Mental Model

```
Process start
  → uvicorn imports app; FastAPI builds routes, dependency graphs (Dependant trees) and OpenAPI lazily
  → lifespan startup: create engine/pools/clients → app.state
Per request
  → ASGI server parses HTTP → scope/receive/send
  → middleware chain (pure ASGI or BaseHTTPMiddleware) → exception middleware
  → router match → solve dependencies (async on loop; sync in AnyIO thread pool)
  → validate path/query/header/cookie/body with Pydantic (422 on failure)
  → endpoint (async on loop | sync in thread pool)
  → response_model validation & serialization → Response
  → yield-dependency teardown, background tasks
Process stop
  → stop accepting → drain in-flight → lifespan shutdown (dispose pools)
```

**Layering for maintainable services:**

```
api/ (routers: HTTP concerns, schemas)  →  services/ (use cases, transactions)
   →  repositories/ (persistence queries)  →  db models / infra clients
domain/ (entities, rules, errors — no framework imports)
core/ (settings, security, logging, telemetry)
```

### 4. Comprehensive Theory

#### 4.1 FastAPI Lifecycle, ASGI and Starlette

- **ASGI** (Asynchronous Server Gateway Interface) defines `async def app(scope, receive, send)`. Uvicorn/Hypercorn/Granian are ASGI servers. Starlette is the ASGI toolkit (routing, requests/responses, middleware, WebSockets, lifespan). FastAPI subclasses Starlette, adding dependency injection, Pydantic validation and OpenAPI generation.
- **Lifespan**: `FastAPI(lifespan=...)` async context manager — the current way to manage startup/shutdown. `@app.on_event("startup")` is **[Deprecated]**.
- **Middleware**: pure ASGI middleware wraps the app and sees raw messages (best performance, works with streaming); `@app.middleware("http")`/`BaseHTTPMiddleware` is convenient but historically had issues with streaming responses and context propagation — prefer pure ASGI for production cross-cutting concerns (request IDs, timing).
- **Exception handling**: `HTTPException` → JSON error; `RequestValidationError` → 422; custom handlers via `@app.exception_handler(DomainError)`; unhandled exceptions → 500 via `ServerErrorMiddleware`. Centralize mapping from domain errors to HTTP (e.g. RFC 9457 Problem Details).
- **Response serialization**: if `response_model` (or return annotation) is set, FastAPI validates/serializes output through Pydantic — filtering fields not in the model (security: prevents leaking `password_hash`). Returning a `Response` directly bypasses this.

#### 4.2 Async vs Sync

| Endpoint | Runs where | Use when | Danger |
|---|---|---|---|
| `async def` | Event loop | All I/O uses async libraries | Any blocking call stalls the whole worker |
| `def` | AnyIO thread pool (default 40 tokens) | Blocking libraries (sync SQLAlchemy, boto3) | Thread-pool exhaustion under slow I/O |

Same applies to dependencies. Mixed: in `async def`, wrap blocking calls with `await anyio.to_thread.run_sync(fn)` / `asyncio.to_thread`. CPU-heavy work → process pool or worker service either way.

#### 4.3 Dependency Injection

```python
from typing import Annotated
from fastapi import Depends

async def get_settings() -> Settings: ...
async def get_session() -> AsyncIterator[AsyncSession]: ...
async def get_current_user(token: Annotated[str, Depends(oauth2_scheme)],
                           session: Annotated[AsyncSession, Depends(get_session)]) -> User: ...

CurrentUser = Annotated[User, Depends(get_current_user)]
SessionDep = Annotated[AsyncSession, Depends(get_session)]

@router.get("/me")
async def me(user: CurrentUser) -> UserOut: ...
```

Key mechanics:
- **Graph resolution**: FastAPI inspects signatures at startup, building a tree; at request time it resolves leaves first.
- **Per-request caching**: the same dependency used multiple times in one request is executed once (`use_cache=True` default) — e.g. `get_session` shared by `get_current_user` and the endpoint, so both see the same session. `Depends(fn, use_cache=False)` to opt out.
- **`yield` dependencies**: code before `yield` is setup; after is teardown; exceptions from the endpoint propagate into the dependency (use `try/except/finally` to rollback). **[Version-dependent]** FastAPI 0.106 changed teardown to run before the response is sent; later releases added `scope` options for `yield` dependencies — check your pinned version's docs for exact semantics, especially with streaming responses.
- **Classes as dependencies**, router-level and app-level `dependencies=[...]` for side-effect-only dependencies (auth checks, rate limits).
- **Testing**: `app.dependency_overrides[get_session] = fake_session` — the main reason to inject rather than import globals.

#### 4.4 Pydantic v2

- Core is `pydantic-core` (Rust); models compile to validators/serializers. 
- `model_config = ConfigDict(extra="forbid", strict=True, from_attributes=True, frozen=True, str_strip_whitespace=True)`.
- `Field(min_length=..., ge=..., pattern=..., examples=[...])`, `Annotated[int, Field(gt=0)]` reusable types.
- Validators: `@field_validator("x", mode="before"|"after")`, `@model_validator(mode="after")`; `@computed_field`; serializers `@field_serializer`.
- `model_validate()`, `model_validate_json()` (fast path from bytes), `model_dump(mode="json", exclude_none=True)`, `model_dump_json()`.
- `TypeAdapter(list[Item])` for validating non-model types.
- **Lax vs strict**: default lax mode coerces `"5"` → `5`; strict mode rejects. Choose strictness at trust boundaries deliberately.
- Separate models: `UserCreate` (input incl. password), `UserUpdate` (all optional; use `model_dump(exclude_unset=True)` for PATCH), `UserOut` (no secrets), DB model (SQLAlchemy).
- Settings: `pydantic-settings` `BaseSettings` with env prefixes, `.env` for local, `SecretStr` for secrets.

#### 4.5 SQLAlchemy 2.x and PostgreSQL

- 2.0-style: `DeclarativeBase`, `Mapped[...]`, `mapped_column()`, `select()` statements, `session.execute(stmt).scalars()`; `AsyncEngine`/`AsyncSession` with asyncpg or psycopg 3.
- **Session per request** via a `yield` dependency; `expire_on_commit=False` for async (avoid implicit lazy refresh after commit, which would require I/O).
- **Lazy loading in async raises** (`MissingGreenlet`) — use `selectinload()`/`joinedload()` or `lazy="raise"` to catch N+1 early.
- **Transactions**: `async with session.begin():` or explicit `commit()`; keep transactions short; no external calls inside.
- **Concurrency**: `with_for_update()`, `skip_locked=True`, optimistic `version_id_col`.
- **Alembic**: autogenerate is a draft — review; zero-downtime migrations (expand → migrate → contract; `CREATE INDEX CONCURRENTLY` outside a transaction; add nullable columns, backfill in batches, then add constraints with `NOT VALID` + `VALIDATE CONSTRAINT`).
- **Query performance**: `EXPLAIN (ANALYZE, BUFFERS)`; composite index order follows equality-then-range; keyset pagination (`WHERE (created_at, id) < (:c, :i) ORDER BY created_at DESC, id DESC LIMIT 50`) instead of large `OFFSET`.

#### 4.6 Security

- **Authentication**: OAuth2/OIDC with an identity provider is preferred for real apps; the app validates JWT access tokens (signature via JWKS, `iss`, `aud`, `exp`, `nbf`; restrict algorithms — never accept `none`; don't use symmetric secrets shared with clients). Password flows: hash with Argon2id or bcrypt (via `pwdlib` or `argon2-cffi`; `passlib` is unmaintained **[Legacy]**). Use `PyJWT` (python-jose is poorly maintained **[Legacy]**).
- **Authorization**: RBAC/permissions as dependencies (`require_permission("orders:write")`); **object-level authorization** in services/repositories (tenant and owner filters) — BOLA is #1 in OWASP API Security Top 10 (2023).
- Cookies vs bearer tokens (CSRF with cookies; XSS risk with tokens in localStorage), CORS configured narrowly, rate limiting, input size limits, security headers, secret management (AWS Secrets Manager/SSM), dependency scanning.

#### 4.7 Redis, Celery, Kafka

- **Redis**: `redis.asyncio` client created in lifespan; caching, rate limiting, locks for efficiency, ephemeral state. Not a durable source of truth unless configured and accepted.
- **Celery**: mature task queue (Redis/RabbitMQ broker). Key settings: `task_acks_late=True`, `worker_prefetch_multiplier=1` for long tasks, `visibility_timeout` > max runtime (Redis broker), retries with `autoretry_for`, `retry_backoff`, `retry_jitter`, idempotent tasks, result backend only when needed. Calling async code from Celery tasks requires an event loop per task/worker; alternatives with native asyncio: **arq**, **Dramatiq** (with asyncio middleware), **SAQ**, **Taskiq**.
- **Kafka**: `aiokafka` or `confluent-kafka` (librdkafka; asyncio support in recent versions); idempotent producer (`enable.idempotence=true`, `acks=all`), keys for ordering, consumer commits after processing, DLQ topics, schema registry for contracts.

#### 4.8 Testing and Observability

- `TestClient` (sync, uses HTTPX under the hood; runs lifespan when used as context manager) and `httpx.AsyncClient(transport=ASGITransport(app))` for async tests.
- Overrides for auth (`dependency_overrides[get_current_user] = lambda: fake_user`).
- Real DB in tests via Testcontainers; transaction-per-test rollback pattern or truncate between tests.
- Observability: structured JSON logs (structlog/stdlib with JSON formatter), request ID middleware, OpenTelemetry instrumentation (FastAPI, SQLAlchemy, httpx, Redis, Celery, Kafka), Prometheus metrics, health endpoints.

### 5. Internal Mechanics

**Dependency solving (simplified).** At route registration, `fastapi.dependencies.utils.get_dependant()` inspects the endpoint signature and recursively builds a `Dependant` with params classified as path/query/header/cookie/body/dependency. At request time, `solve_dependencies()` walks the tree, using a per-request cache keyed by `(callable, scopes)`, entering `yield` dependencies on an `AsyncExitStack` so teardown runs in reverse order. Sync callables go through `run_in_threadpool` (AnyIO). Validation errors are collected across all params and raised together as one 422.

**Body parsing.** `await request.body()` (or form/multipart parsing via `python-multipart`), then Pydantic validation of the combined body model. JSON is parsed by Pydantic's Rust parser when possible.

**Response.** Endpoint return → `serialize_response()` validates against the response field → `jsonable_encoder`/Pydantic serialization → `JSONResponse`. **[Version-dependent]** Recent FastAPI versions serialize Pydantic return values directly through Pydantic's JSON serializer for speed when a response model is declared.

### 6. Implementation Examples

#### Example 1 — Minimal: Typed CRUD with in-memory repository (the 60-minute baseline skeleton)

```python
# app/main.py
import uuid
from typing import Annotated

from fastapi import Depends, FastAPI, HTTPException, Query, status
from pydantic import BaseModel, ConfigDict, Field

app = FastAPI(title="Tasks")


class TaskCreate(BaseModel):
    model_config = ConfigDict(extra="forbid")
    title: str = Field(min_length=1, max_length=200)
    done: bool = False


class TaskOut(TaskCreate):
    id: uuid.UUID


class TaskRepo:
    def __init__(self) -> None:
        self._items: dict[uuid.UUID, TaskOut] = {}

    def add(self, data: TaskCreate) -> TaskOut:
        task = TaskOut(id=uuid.uuid4(), **data.model_dump())
        self._items[task.id] = task
        return task

    def get(self, task_id: uuid.UUID) -> TaskOut | None:
        return self._items.get(task_id)

    def list(self, done: bool | None, limit: int, offset: int) -> list[TaskOut]:
        items = [t for t in self._items.values() if done is None or t.done == done]
        return items[offset: offset + limit]

    def delete(self, task_id: uuid.UUID) -> bool:
        return self._items.pop(task_id, None) is not None


_repo = TaskRepo()
def get_repo() -> TaskRepo:
    return _repo

Repo = Annotated[TaskRepo, Depends(get_repo)]


@app.post("/tasks", status_code=status.HTTP_201_CREATED, response_model=TaskOut)
def create_task(body: TaskCreate, repo: Repo) -> TaskOut:
    return repo.add(body)


@app.get("/tasks", response_model=list[TaskOut])
def list_tasks(repo: Repo, done: bool | None = None,
               limit: Annotated[int, Query(ge=1, le=100)] = 20,
               offset: Annotated[int, Query(ge=0)] = 0) -> list[TaskOut]:
    return repo.list(done, limit, offset)


@app.get("/tasks/{task_id}", response_model=TaskOut)
def get_task(task_id: uuid.UUID, repo: Repo) -> TaskOut:
    if (task := repo.get(task_id)) is None:
        raise HTTPException(status.HTTP_404_NOT_FOUND, "Task not found")
    return task


@app.delete("/tasks/{task_id}", status_code=status.HTTP_204_NO_CONTENT)
def delete_task(task_id: uuid.UUID, repo: Repo) -> None:
    if not repo.delete(task_id):
        raise HTTPException(status.HTTP_404_NOT_FOUND, "Task not found")
```

#### Example 2 — Realistic: Auth with JWT + RBAC + filtering (the 90-minute increment)

```python
# app/core/security.py
from datetime import UTC, datetime, timedelta
from typing import Annotated

import jwt                                     # PyJWT
from fastapi import Depends, HTTPException, status
from fastapi.security import OAuth2PasswordBearer
from pwdlib import PasswordHash
from pydantic import BaseModel

from app.core.config import settings

oauth2_scheme = OAuth2PasswordBearer(tokenUrl="/auth/token")
password_hash = PasswordHash.recommended()      # Argon2id


class TokenClaims(BaseModel):
    sub: str
    roles: list[str]
    tenant_id: str
    exp: int


def create_access_token(sub: str, roles: list[str], tenant_id: str) -> str:
    exp = datetime.now(UTC) + timedelta(minutes=settings.access_token_minutes)
    payload = {"sub": sub, "roles": roles, "tenant_id": tenant_id, "exp": exp,
               "iss": settings.jwt_issuer, "aud": settings.jwt_audience}
    return jwt.encode(payload, settings.jwt_secret.get_secret_value(), algorithm="HS256")


async def get_claims(token: Annotated[str, Depends(oauth2_scheme)]) -> TokenClaims:
    try:
        data = jwt.decode(token, settings.jwt_secret.get_secret_value(), algorithms=["HS256"],
                          audience=settings.jwt_audience, issuer=settings.jwt_issuer)
    except jwt.PyJWTError:
        raise HTTPException(status.HTTP_401_UNAUTHORIZED, "Invalid token",
                            headers={"WWW-Authenticate": "Bearer"})
    return TokenClaims.model_validate(data)


def require_role(*allowed: str):
    async def checker(claims: Annotated[TokenClaims, Depends(get_claims)]) -> TokenClaims:
        if not set(allowed) & set(claims.roles):
            raise HTTPException(status.HTTP_403_FORBIDDEN, "Insufficient role")
        return claims
    return checker
```

(For production with an external IdP, verify RS256/ES256 tokens against the provider's JWKS instead of a shared HS256 secret.)

Filtering pattern: a `TaskFilter` Pydantic model as a dependency (`Annotated[TaskFilter, Query()]` — **[Version-dependent]** query-parameter models are supported in FastAPI ≥ 0.115) translating to SQLAlchemy `where` clauses, always including `tenant_id == claims.tenant_id`.

# app/db/session.py
from collections.abc import AsyncIterator
from sqlalchemy.ext.asyncio import AsyncSession, async_sessionmaker, create_async_engine

from app.core.config import settings

engine = create_async_engine(settings.database_url, pool_size=5, max_overflow=5,

```python
# app/services/tasks.py
import uuid
from sqlalchemy import select
from sqlalchemy.ext.asyncio import AsyncSession

from app.db.models import Task
from app.domain.errors import NotFound


class TaskService:
    def __init__(self, session: AsyncSession, cache, queue) -> None:
        self.session, self.cache, self.queue = session, cache, queue

    async def create(self, tenant_id: str, owner_id: str, title: str) -> Task:
        task = Task(tenant_id=tenant_id, owner_id=owner_id, title=title)
        self.session.add(task)
        await self.session.commit()
        await self.queue.enqueue("index_task", task_id=str(task.id))   # durable job (arq/Celery)
        return task

    async def get(self, tenant_id: str, task_id: uuid.UUID) -> dict:
        async def load() -> dict:
            row = (await self.session.execute(
                select(Task).where(Task.id == task_id, Task.tenant_id == tenant_id)
            )).scalar_one_or_none()
            if row is None:
                raise NotFound("task")
            return {"id": str(row.id), "title": row.title, "done": row.done}
        return await self.cache.get_or_load(f"t:{tenant_id}:task:{task_id}", load, ttl_s=120)
```

### 7. Comparative Analysis

| Comparison | Key difference | Trap |
|---|---|---|
| `async def` vs `def` endpoint | Event loop vs thread pool | Blocking call in `async def` |
| Middleware vs dependency | All requests, raw ASGI vs per-route, typed, testable | Auth in middleware without route context |
| `BackgroundTasks` vs Celery/arq | In-process, losable vs durable | Critical emails via BackgroundTasks |
| `HTTPException` vs domain exception vs `ValidationError` | HTTP concern vs business rule vs input shape | Raising HTTPException deep in domain code |
| Pydantic lax vs strict | Coerce vs reject | Unexpected coercion of `"true"`/`1` |
| `response_model` vs return type | Explicit filter vs inferred | Returning ORM objects with secrets without a response model |
| Sessions: per request vs global | Isolation vs shared state chaos | Global session shared across concurrent requests |
| `selectinload` vs `joinedload` | Second IN query vs JOIN | Joinedload on collections multiplying rows |
| OFFSET vs keyset pagination | Simple vs scalable/consistent | OFFSET 100000 scans |
| JWT vs opaque session tokens | Stateless verification vs revocable server state | "JWT means secure"; no revocation strategy |
| ECS Fargate vs EKS | Simpler managed vs flexible/portable | Choosing Kubernetes for a 2-service app |

### 8. Failure Modes and Debugging

**B1 — `MissingGreenlet` / `greenlet_spawn has not been called`.** CAUSE: lazy loading a relationship in async context (often during response serialization). FIX: eager load with `selectinload`, or map to DTO inside the session. PREVENT: `lazy="raise"` on relationships.

**B2 — 422 errors after a client change.** INVESTIGATE: the 422 body lists `loc`, `msg`, `type`; compare OpenAPI schema versions. FIX: backward-compatible schema evolution (optional new fields), versioning. PREVENT: contract tests, OpenAPI diff in CI (`oasdiff`).

**B3 — Connections exhausted ("QueuePool limit … reached, connection timed out").** CAUSE: sessions not closed (no `yield` dependency), long transactions, too many workers. FIX: session lifecycle, pool sizing, PgBouncer. PREVENT: pool metrics and alerts.

**B4 — Slow list endpoint.** INVESTIGATE: OTel trace shows 101 DB spans → N+1; `EXPLAIN ANALYZE` shows Seq Scan. FIX: eager loading, composite index `(tenant_id, created_at)`, keyset pagination.

**B5 — Intermittent 401s after deploy.** CAUSE: JWT secret/JWKS rotation mismatch across pods; clock skew. FIX: support multiple keys (kid), `leeway` for clock skew, staged rotation.

**B6 — Celery tasks run twice.** CAUSE: Redis broker visibility timeout < task duration with `acks_late`. FIX: raise visibility timeout, make tasks idempotent.

**B7 — Migration locks table in production.** CAUSE: `ALTER TABLE ... ADD COLUMN ... DEFAULT volatile` or non-concurrent index build. FIX: expand/contract, `CREATE INDEX CONCURRENTLY`, `lock_timeout`. PREVENT: migration linting (e.g. squawk), staging rehearsal on production-sized data.

**Incident-question technique (use aloud in interviews):** *Stabilize* (rollback, scale, shed load, feature flag) → *Scope* (which endpoints/tenants, since when, what changed) → *Diagnose* (metrics → traces → logs → profiles → DB views) → *Fix* → *Verify* → *Prevent* (tests, alerts, runbook, postmortem).

### 13. Interview Preparation

#### Quick Questions

**Q: Walk me through a FastAPI request.**
Strong: ASGI server parses and calls the app; middleware runs; router matches; dependencies resolve (async on loop, sync in thread pool) with per-request caching; Pydantic validates inputs (422 on failure); endpoint runs; output validated/serialized via response model; yield-dependency teardown and background tasks run; middleware completes.

**Q: async vs sync endpoint?**
Strong: `async def` runs on the event loop — use only non-blocking I/O; `def` runs in a thread pool of ~40 — good for blocking libraries. Blocking in async stalls all requests in that worker.

**Q: How do you manage DB sessions?**
Strong: One `AsyncSession` per request from a `yield` dependency; commit in the service layer; rollback on exception; close in teardown; engine created once in lifespan; pool sized to DB limits.

**Q: What does `Depends` caching mean?**
Strong: Within one request, a dependency used in multiple places runs once and its result is shared — so the auth dependency and the endpoint get the same session.

#### Intermediate Questions

**Q: How would you implement authentication and authorization?**
Strong: Delegate authentication to an IdP via OIDC; validate access tokens (signature via JWKS, iss/aud/exp, allowed algorithms) in a dependency producing a `Principal`; enforce permissions with dependencies (`require_permission`) and object-level checks in services/repositories (tenant/owner filters). Hash passwords with Argon2id if you own credentials. Log auth failures; rate-limit login.
Trap: "JWT makes it secure"; checking roles only in the frontend.

**Q: How do you test a FastAPI app?**
Strong: Pyramid: unit tests for services; API tests with HTTPX and dependency overrides; integration tests with real Postgres/Redis via Testcontainers and migrations; contract/OpenAPI tests; a few E2E smoke tests post-deploy.

**Q: How do you scale FastAPI?**
Strong: (Ties to Unit 47.) Stateless replicas, process-per-core or container-per-process, async I/O, connection pooling/PgBouncer, caching, background workers for slow work, autoscaling on meaningful metrics, and load testing.

#### Advanced Questions

**Q: Your async endpoint's p99 is 10× p50 only under load. Diagnose.**
Strong: Check event-loop lag (blocking code), pool wait times, thread-pool saturation from sync deps, GC pauses, downstream tail latency; traces to locate gaps; py-spy to find blocking frames; fix and verify with load test.

**Q: How do you do zero-downtime deployments with DB migrations?**
Strong: Backward-compatible expand/contract migrations run before deploying code that needs them; code tolerates both schemas; rolling or blue/green deploy with readiness gates and connection draining; contract phase after all old code is gone; concurrent index builds; lock timeouts; rollback plan.

**Q: Design the production deployment on AWS.**
Strong: ALB + WAF → ECS Fargate across 3 AZs (autoscaling) → RDS Postgres Multi-AZ + RDS Proxy → ElastiCache → SQS/MSK + worker services → Secrets Manager, IAM roles → OTel collector → CloudWatch/X-Ray or vendor → CI/CD with image scanning and canary/blue-green; alarms on SLO burn.

```python
# (2) Pure ASGI request-ID middleware
import uuid
from contextvars import ContextVar

request_id_var: ContextVar[str] = ContextVar("request_id", default="-")


class RequestIDMiddleware:
    def __init__(self, app) -> None:
        self.app = app

    async def __call__(self, scope, receive, send):
        if scope["type"] != "http":
            return await self.app(scope, receive, send)
        headers = dict(scope["headers"])
        rid = headers.get(b"x-request-id", b"").decode() or uuid.uuid4().hex
        token = request_id_var.set(rid)

        async def send_wrapper(message):
            if message["type"] == "http.response.start":
                message.setdefault("headers", []).append((b"x-request-id", rid.encode()))
            await send(message)

        try:
            await self.app(scope, receive, send_wrapper)
        finally:
            request_id_var.reset(token)
```

### 14. Explain-It-at-Three-Levels

**Dependency injection in FastAPI.** *30 s:* Declare what an endpoint needs with `Depends`; FastAPI builds and provides it per request, caches it within the request, and tears it down after — which makes testing easy via overrides. *2 min:* Graph resolution, sub-dependencies, `yield` teardown, caching, router-level dependencies, overrides. *Deep:* `Dependant` trees built at startup, `AsyncExitStack` teardown, thread-pool execution of sync deps, scope semantics changes across versions, and how security schemes integrate with OpenAPI.

**DB session lifecycle.** *30 s:* One session per request via a yield dependency, short transactions, close in teardown. *2 min:* Engine and pool in lifespan, `expire_on_commit=False`, eager loading in async, rollback on error. *Deep:* Pool checkout/return, `pool_pre_ping`, PgBouncer transaction pooling caveats (prepared statements with asyncpg — disable statement cache or use psycopg 3), isolation levels and locking.

#### Knowledge Check Answers

1. FastAPI runs sync dependencies in the AnyIO thread pool, not on the event loop.
2. It filters the output to declared fields, preventing accidental exposure of internal fields like password hashes.
3. Adding nullable columns without defaults is a metadata-only change (fast); backfill in batches; then add NOT NULL via validated constraint — avoids long locks and rewrites.
4. After commit, attributes would otherwise expire and access would trigger implicit I/O (lazy refresh), which is not allowed implicitly in async.
5. 401: not authenticated (missing/invalid credentials). 403: authenticated but not permitted.
6. The `async def` endpoint executes a blocking sync DB query on the event loop (the dependency runs in a thread, but `db.query(...).all()` runs in the endpoint on the loop). Use `def` endpoint or async session; also no pagination or response model.
7. Session is never closed (no `finally`/context manager) → connection leaks; no rollback on errors.
8. Missing object-level authorization (BOLA): any authenticated user can read any order; also returns ORM object without a response model.
9. Async fixtures/clients bound to different event loops across tests (e.g. engine created at import time on one loop, tests on another). Use session-scoped `anyio_backend`/loop config consistently and create resources inside fixtures; dispose engines.
10. Pods removed from load balancer after they stop accepting connections (or without draining). Fix: readiness flip + `preStop` sleep, graceful shutdown timeout, ALB deregistration delay alignment.
11. arq (or Taskiq/SAQ) fits async-native code with simpler ops; Celery has richer features (canvas, scheduling, mature monitoring) but async tasks need adaptation. Choose based on features needed and operational familiarity.
12. Short-lived access tokens (5–15 min) + refresh tokens stored server-side and revocable; for immediate revocation, a denylist of `jti` in Redis checked on sensitive operations; or opaque tokens with introspection for high-security contexts.
