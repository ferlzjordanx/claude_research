## Unit 51 — Coding Interview Track

### 1. Learning Objectives

1. **Apply** the eight-step method — clarify → examples → brute force → pattern → optimize → implement → test → Big-O — to every problem, out loud.
2. **Recognize** problem signals that map to patterns: hashing, two pointers, sliding window, prefix sums, binary search (including on the answer), stacks/monotonic stacks, queues/BFS, linked-list manipulation, heaps, tree traversal, graph search, topological sort, union-find, intervals, backtracking, dynamic programming and bit manipulation.
3. **Implement** each pattern idiomatically in Python without hiding the algorithm behind library shortcuts (and **explain** when a library call is acceptable).
4. **Analyze** time and space complexity, including amortized costs, recursion stack space, and Python-specific costs (slicing copies, string immutability, `in` on lists).
5. **Test** solutions with edge cases (empty, single element, duplicates, negatives, overflow-equivalent large values, disconnected graphs, cycles) and **debug** off-by-one and state errors systematically.
6. **Communicate** clearly: think aloud, state invariants, propose trade-offs, and respond to hints.

### 2. Prerequisite Knowledge

Python collections and complexities (Unit 49 §4.6), recursion, basic discrete math (logarithms, sums, combinatorics). Familiarity with `collections.deque`, `heapq`, `bisect`, `functools.cache`.

**Big-O refresher.** n ≤ 10 → O(n!) ok; n ≤ 20 → O(2ⁿ); n ≤ 500 → O(n³); n ≤ 5,000 → O(n²); n ≤ 10⁶ → O(n log n) or O(n); larger → O(n) or O(log n). Python executes roughly 10⁷–10⁸ simple operations per second, so constant factors matter more than in C++.

### 3. Mental Model

```
Problem statement
  → constraints (n size, value ranges, sorted? unique? streaming?)  ← the biggest hint
  → what is being asked? (existence, count, min/max, all solutions, construct)
  → brute force (correctness baseline + complexity)
  → bottleneck: repeated work? unnecessary search? ordering property?
  → pattern that removes the bottleneck
  → invariant that makes the pattern correct
  → implementation → tests → complexity
```

**Signal → pattern map.**

| Signal | Likely pattern |
|---|---|
| "pair/complement/seen before", O(n) wanted | Hash map/set |
| Sorted array; pairs/triplets; in-place partitioning | Two pointers |
| Contiguous subarray/substring with constraint | Sliding window |
| Subarray sums, range queries | Prefix sums (+ hash map) |
| Sorted / monotonic predicate / "minimum X such that" | Binary search (on index or answer) |
| Matching brackets, "next greater", undo | Stack / monotonic stack |
| Shortest path unweighted, level order | BFS with queue |
| Top-k, streaming median, k-way merge, scheduling | Heap |
| Hierarchical data, recursion on structure | Tree DFS/BFS |
| Dependencies, connectivity, cycles | Graph DFS/BFS, topo sort, union-find |
| Overlapping ranges, meeting rooms | Sort intervals + sweep |
| All combinations/permutations/subsets with constraints | Backtracking |
| Optimal value with overlapping subproblems | Dynamic programming |
| Parity, subsets as masks, XOR tricks | Bit manipulation |

#### 4.1 Arrays, Strings, Hash Maps and Sets

**Idea.** Trade space for time: store what you've seen for O(1) average lookups.

**Worked problem — Two Sum (return indices of two numbers adding to target).**
1. *Clarify:* exactly one solution? same element twice? negative numbers? return order? → assume one solution, distinct indices.
2. *Examples:* `[2,7,11,15], 9 → [0,1]`; `[3,3], 6 → [0,1]`.
3. *Brute force:* check all pairs, O(n²) time, O(1) space.
4. *Pattern:* "complement seen before" → hash map value → index.
5. *Optimize:* one pass; check complement before inserting current (handles duplicates).
6. *Implement:*
```python
def two_sum(nums: list[int], target: int) -> list[int]:
    seen: dict[int, int] = {}
    for i, x in enumerate(nums):
        j = seen.get(target - x)
        if j is not None:
            return [j, i]
        seen[x] = i
    raise ValueError("no solution")
```
7. *Test:* duplicates `[3,3]`, negatives `[-1,-2,-3], -5`, solution at end, no solution.
8. *Big-O:* O(n) time, O(n) space.

**Python notes.** String building: `"".join(parts)` (O(n)) not `s += c` in loops; `Counter` is fine but be able to write the dict counting loop; sorting is O(n log n) (Timsort, stable).

**Common mistakes.** Inserting before checking (matching an element with itself); using a list for membership (`in` is O(n)).

#### 4.2 Two Pointers

**Idea.** Two indices moving according to an invariant, usually on sorted data or for in-place transformation.

**Worked problem — 3Sum (unique triplets summing to 0).**
Clarify: unique triplets by value; input size up to 3,000. Brute force O(n³). Pattern: sort + fix one + two-pointer for pair → O(n²). Skip duplicates at all three positions.

```python
def three_sum(nums: list[int]) -> list[list[int]]:
    nums = sorted(nums)
    res: list[list[int]] = []
    n = len(nums)
    for i in range(n - 2):
        if nums[i] > 0:
            break                                    # remaining are positive
        if i > 0 and nums[i] == nums[i - 1]:
            continue
        lo, hi = i + 1, n - 1
        while lo < hi:
            s = nums[i] + nums[lo] + nums[hi]
            if s < 0:
                lo += 1
            elif s > 0:
                hi -= 1
            else:
                res.append([nums[i], nums[lo], nums[hi]])
                lo += 1
                hi -= 1
                while lo < hi and nums[lo] == nums[lo - 1]:
                    lo += 1
    return res
```
Invariant: for fixed `i`, all pairs outside `[lo, hi]` have been considered. Time O(n²), space O(n) for the sorted copy (O(1) extra if sorting in place is allowed). Tests: all zeros, no solution, many duplicates.

Other two-pointer forms: fast/slow (cycle detection, middle of list), read/write pointers (remove duplicates in place), opposite ends (container with most water, palindrome check).

#### 4.3 Sliding Window

**Idea.** Maintain a window `[left, right]` over a sequence; expand right; shrink left while the window violates a constraint. Each index enters and leaves once → O(n).

**Template (variable window, pseudocode).**
```text
def longest_window(s):
    state = ...                 # counts, sum, etc.
    left = best = 0
    for right, ch in enumerate(s):
        add ch to state
        while window invalid:
            remove s[left] from state
            left += 1
        best = max(best, right - left + 1)
    return best
```

**Worked problem — Longest substring without repeating characters.**
```python
def length_of_longest_substring(s: str) -> int:
    last_seen: dict[str, int] = {}
    left = best = 0
    for right, ch in enumerate(s):
        if ch in last_seen and last_seen[ch] >= left:
            left = last_seen[ch] + 1                 # jump past the previous occurrence
        last_seen[ch] = right
        best = max(best, right - left + 1)
    return best
```
O(n) time, O(min(n, alphabet)) space. Edge cases: empty string, all same characters, `"abba"` (the `>= left` check matters).

**When sliding window fails:** with negative numbers, "sum ≥ k" windows aren't monotonic → use prefix sums + monotonic deque or hash map.

#### 4.4 Prefix Sums

**Idea.** `prefix[i] = sum(nums[:i])`; any subarray sum `nums[i:j] = prefix[j] - prefix[i]` in O(1).

**Worked problem — Count subarrays summing to k (with negatives).**
Brute force O(n²). Insight: count earlier prefixes equal to `current - k`.
```python
from collections import defaultdict

def subarray_sum(nums: list[int], k: int) -> int:
    count_of_prefix: defaultdict[int, int] = defaultdict(int)
    count_of_prefix[0] = 1                           # empty prefix
    running = total = 0
    for x in nums:
        running += x
        total += count_of_prefix[running - k]
        count_of_prefix[running] += 1
    return total
```
O(n)/O(n). Mistake: forgetting the `{0: 1}` base case. Extensions: 2D prefix sums for matrix region queries; difference arrays for range updates.

#### 4.5 Binary Search

**Idea.** Halve the search space using a monotonic predicate. Two flavors: search in sorted array; **binary search on the answer** ("minimum capacity such that feasible(capacity)").

**Template (first index where predicate is true).**
```python
def first_true(lo: int, hi: int, pred) -> int:
    """Smallest x in [lo, hi) with pred(x) True; returns hi if none. pred must be monotonic F..FT..T."""
    while lo < hi:
        mid = (lo + hi) // 2
        if pred(mid):
            hi = mid
        else:
            lo = mid + 1
    return lo
```

**Worked problem — Minimum ship capacity to ship packages within D days.**
Answer lies in `[max(weights), sum(weights)]`; feasibility is monotonic in capacity.
```python
def ship_within_days(weights: list[int], days: int) -> int:
    def feasible(cap: int) -> bool:
        used, load = 1, 0
        for w in weights:
            if load + w > cap:
                used += 1
                load = 0
            load += w
        return used <= days

    return first_true(max(weights), sum(weights) + 1, feasible)
```
O(n log S) time. Mistakes: wrong bounds, infinite loops from `lo = mid`, non-monotonic predicates. `bisect.bisect_left` is acceptable for plain sorted lookups once you can write it yourself.

#### 4.6 Stacks and Queues (incl. Monotonic Stack)

**Stack worked problem — Valid parentheses.** Push openers; on closer, check top matches. O(n).
```python
def is_valid(s: str) -> bool:
    pairs = {")": "(", "]": "[", "}": "{"}
    stack: list[str] = []
    for ch in s:
        if ch in pairs:
            if not stack or stack.pop() != pairs[ch]:
                return False
        else:
            stack.append(ch)
    return not stack
```

**Monotonic stack — Daily temperatures (days until warmer).** Keep indices with decreasing temperatures; when a warmer day arrives, pop and resolve.
```python
def daily_temperatures(t: list[int]) -> list[int]:
    ans = [0] * len(t)
    stack: list[int] = []                            # indices, temperatures strictly decreasing
    for i, temp in enumerate(t):
        while stack and t[stack[-1]] < temp:
            j = stack.pop()
            ans[j] = i - j
        stack.append(i)
    return ans
```
Each index pushed/popped once → O(n). Queues: `collections.deque` (never `list.pop(0)`, which is O(n)). Monotonic deque for sliding-window maximum.

#### 4.7 Linked Lists

Key techniques: dummy head node, fast/slow pointers, in-place reversal, merging.

```python
from dataclasses import dataclass

@dataclass
class ListNode:
    val: int
    next: "ListNode | None" = None


def reverse(head: ListNode | None) -> ListNode | None:
    prev = None
    while head:
        head.next, prev, head = prev, head, head.next   # careful: RHS evaluated first
    return prev


def has_cycle(head: ListNode | None) -> bool:
    slow = fast = head
    while fast and fast.next:
        slow, fast = slow.next, fast.next.next
        if slow is fast:
            return True
    return False
```
Mistakes: losing the reference to `next` before relinking; forgetting to handle `None`; the tuple-assignment order trick is error-prone — write three lines if unsure in an interview.

#### 4.8 Heaps

**Idea.** `heapq` is a binary min-heap on a list: push/pop O(log n), peek O(1), heapify O(n).

**Worked problem — K closest points to origin.** Maintain a max-heap of size k (negate distances).
```python
import heapq

def k_closest(points: list[list[int]], k: int) -> list[list[int]]:
    heap: list[tuple[int, int, int]] = []           # (-dist, x, y)
    for x, y in points:
        d = x * x + y * y
        if len(heap) < k:
            heapq.heappush(heap, (-d, x, y))
        elif -heap[0][0] > d:
            heapq.heapreplace(heap, (-d, x, y))
    return [[x, y] for _, x, y in heap]
```
O(n log k) time, O(k) space. Other uses: merge k sorted lists, running median (two heaps), task scheduling, Dijkstra. Tie-breaking: include a counter in tuples when items aren't comparable.

#### 4.9 Trees

Traversals: preorder/inorder/postorder (DFS, recursive or iterative with stack), level-order (BFS). BST property enables O(h) search. Recursion depth: Python's default limit is ~1,000 — use iterative traversal for deep/degenerate trees.

**Worked problem — Validate a BST.** Pass down allowed bounds.
```python
from dataclasses import dataclass
from math import inf

@dataclass
class TreeNode:
    val: int
    left: "TreeNode | None" = None
    right: "TreeNode | None" = None


def is_valid_bst(root: TreeNode | None) -> bool:
    stack: list[tuple[TreeNode | None, float, float]] = [(root, -inf, inf)]
    while stack:
        node, lo, hi = stack.pop()
        if node is None:
            continue
        if not (lo < node.val < hi):
            return False
        stack.append((node.left, lo, node.val))
        stack.append((node.right, node.val, hi))
    return True
```
Common mistake: only comparing a node with its direct children. Other classics: max depth, lowest common ancestor, diameter, serialize/deserialize, level-order traversal, path sum.

#### 4.10 Graphs

Representations: adjacency list (`dict[node, list[node]]`) for sparse graphs. BFS for shortest path in unweighted graphs; DFS for reachability, components, cycle detection; Dijkstra (heap) for non-negative weights; topological sort (Kahn's algorithm) for DAG ordering; union-find for dynamic connectivity.

**Worked problem — Course schedule (can all courses be finished?).** Cycle detection via Kahn's algorithm.
```python
from collections import deque

def can_finish(num_courses: int, prerequisites: list[list[int]]) -> bool:
    graph: list[list[int]] = [[] for _ in range(num_courses)]
    indegree = [0] * num_courses
    for course, pre in prerequisites:
        graph[pre].append(course)
        indegree[course] += 1

    queue = deque(i for i in range(num_courses) if indegree[i] == 0)
    taken = 0
    while queue:
        node = queue.popleft()
        taken += 1
        for nxt in graph[node]:
            indegree[nxt] -= 1
            if indegree[nxt] == 0:
                queue.append(nxt)
    return taken == num_courses
```
O(V + E). **Grid BFS** (number of islands, shortest path in a maze): mark visited when enqueuing, not when dequeuing, to avoid duplicates.

**Union-Find with path compression and union by rank** — near O(1) amortized (inverse Ackermann):
```python
class DSU:
    def __init__(self, n: int) -> None:
        self.parent = list(range(n))
        self.rank = [0] * n

    def find(self, x: int) -> int:
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]   # path halving
            x = self.parent[x]
        return x

    def union(self, a: int, b: int) -> bool:
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False
        if self.rank[ra] < self.rank[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        if self.rank[ra] == self.rank[rb]:
            self.rank[ra] += 1
        return True
```

#### 4.11 Intervals

Sort by start, then sweep. **Merge intervals:**
```python
def merge(intervals: list[list[int]]) -> list[list[int]]:
    intervals = sorted(intervals, key=lambda iv: iv[0])
    merged: list[list[int]] = []
    for start, end in intervals:
        if merged and start <= merged[-1][1]:
            merged[-1][1] = max(merged[-1][1], end)
        else:
            merged.append([start, end])
    return merged
```
O(n log n). **Meeting rooms II** (min rooms): sort starts; min-heap of end times — or sweep line over sorted start and end arrays. Clarify whether `[1,2]` and `[2,3]` overlap (closed vs half-open intervals).

#### 4.12 Backtracking

**Idea.** DFS over a decision tree; choose → explore → un-choose; prune invalid branches early.

**Worked problem — Subsets / combination sum.**
```python
def combination_sum(candidates: list[int], target: int) -> list[list[int]]:
    candidates = sorted(candidates)
    res: list[list[int]] = []
    path: list[int] = []

    def dfs(start: int, remaining: int) -> None:
        if remaining == 0:
            res.append(path.copy())                  # copy! path is mutated later
            return
        for i in range(start, len(candidates)):
            c = candidates[i]
            if c > remaining:
                break                                # prune (sorted)
            path.append(c)
            dfs(i, remaining - c)                    # i, not i+1: reuse allowed
            path.pop()

    dfs(0, target)
    return res
```
Complexity is exponential; describe it as O(branches^depth) and explain pruning. Mistakes: appending `path` without copying; duplicates when the input has duplicates (sort and skip `i > start and c == candidates[i-1]`).

#### 4.13 Dynamic Programming

**Idea.** Optimal substructure + overlapping subproblems → cache solutions. Steps: define state → recurrence → base cases → order of computation → answer location → optimize space.

**Worked problem — Coin change (minimum coins).**
- State: `dp[a]` = min coins for amount `a`.
- Recurrence: `dp[a] = min(dp[a - c] + 1 for c in coins if c <= a)`.
- Base: `dp[0] = 0`.
```python
def coin_change(coins: list[int], amount: int) -> int:
    INF = amount + 1
    dp = [0] + [INF] * amount
    for a in range(1, amount + 1):
        for c in coins:
            if c <= a and dp[a - c] + 1 < dp[a]:
                dp[a] = dp[a - c] + 1
    return dp[amount] if dp[amount] != INF else -1
```
O(amount × |coins|) time, O(amount) space. Top-down alternative with `@functools.cache` is fine for explanation but watch recursion depth.

**Worked problem — Longest common subsequence (2D DP, space-optimized).**
```python
def lcs(a: str, b: str) -> int:
    prev = [0] * (len(b) + 1)
    for ch_a in a:
        cur = [0] * (len(b) + 1)
        for j, ch_b in enumerate(b, start=1):
            cur[j] = prev[j - 1] + 1 if ch_a == ch_b else max(prev[j], cur[j - 1])
        prev = cur
    return prev[-1]
```
DP families: 1D (climbing stairs, house robber), knapsack (0/1 and unbounded), grid paths, string DP (edit distance, LCS), interval DP, DP on trees, bitmask DP.

#### 4.14 Bit Manipulation

- `x & (x - 1)` clears lowest set bit (power-of-two test: `x > 0 and x & (x-1) == 0`).
- `x & -x` isolates lowest set bit.
- XOR: `a ^ a = 0`, `a ^ 0 = a` → single number among pairs.
- Masks for subsets: iterate `mask in range(1 << n)`; check bit `mask >> i & 1`.
- Python ints are arbitrary precision; negative numbers behave as infinite two's complement — emulate 32-bit with `& 0xFFFFFFFF` when the problem requires.
- `int.bit_count()` (3.10+) for popcount; be able to write Kernighan's loop.

```python
def single_number(nums: list[int]) -> int:
    acc = 0
    for x in nums:
        acc ^= x
    return acc
```

#### Example 1 — Minimal: The full method on "Valid Anagram"
Clarify (Unicode? case?), examples, brute force (sort both: O(n log n)), pattern (counting), implement (dict counts with early exit), test (different lengths, empty), complexity O(n)/O(k).

```python
def is_anagram(s: str, t: str) -> bool:
    if len(s) != len(t):
        return False
    counts: dict[str, int] = {}
    for ch in s:
        counts[ch] = counts.get(ch, 0) + 1
    for ch in t:
        remaining = counts.get(ch, 0) - 1
        if remaining < 0:
            return False
        counts[ch] = remaining
    return True
```

#### Example 2 — Realistic: LRU cache from scratch (common in backend-flavored coding rounds)

```python
class _Node:
    __slots__ = ("key", "val", "prev", "next")

    def __init__(self, key: int = 0, val: int = 0) -> None:
        self.key, self.val = key, val
        self.prev: "_Node | None" = None
        self.next: "_Node | None" = None


class LRUCache:
    """O(1) get/put using hash map + doubly linked list with sentinels."""

    def __init__(self, capacity: int) -> None:
        self.cap = capacity
        self.map: dict[int, _Node] = {}
        self.head, self.tail = _Node(), _Node()      # head.next = most recent
        self.head.next, self.tail.prev = self.tail, self.head

    def _unlink(self, node: _Node) -> None:
        node.prev.next, node.next.prev = node.next, node.prev

    def _push_front(self, node: _Node) -> None:
        node.prev, node.next = self.head, self.head.next
        self.head.next.prev = node
        self.head.next = node

    def get(self, key: int) -> int:
        node = self.map.get(key)
        if node is None:
            return -1
        self._unlink(node)
        self._push_front(node)
        return node.val

    def put(self, key: int, value: int) -> None:
        if (node := self.map.get(key)) is not None:
            node.val = value
            self._unlink(node)
            self._push_front(node)
            return
        if len(self.map) == self.cap:
            lru = self.tail.prev
            self._unlink(lru)
            del self.map[lru.key]
        node = _Node(key, value)
        self.map[key] = node
        self._push_front(node)
```
Mention `OrderedDict.move_to_end` as the idiomatic shortcut — and that the interviewer usually wants the underlying structure.

#### Example 3 — Production-flavored: Dijkstra with path reconstruction and tests

```python
import heapq
from collections.abc import Hashable, Mapping, Sequence


def dijkstra(graph: Mapping[Hashable, Sequence[tuple[Hashable, float]]],
             source: Hashable, target: Hashable) -> tuple[float, list[Hashable]]:
    """Shortest path for non-negative weights. Returns (inf, []) if unreachable."""
    dist: dict[Hashable, float] = {source: 0.0}
    prev: dict[Hashable, Hashable] = {}
    heap: list[tuple[float, int, Hashable]] = [(0.0, 0, source)]
    counter = 1                                      # tie-breaker: nodes may not be comparable
    visited: set[Hashable] = set()
    while heap:
        d, _, node = heapq.heappop(heap)
        if node in visited:
            continue                                 # stale entry (lazy deletion)
        visited.add(node)
        if node == target:
            break
        for nxt, w in graph.get(node, ()):
            if w < 0:
                raise ValueError("negative edge weight")
            nd = d + w
            if nd < dist.get(nxt, float("inf")):
                dist[nxt], prev[nxt] = nd, node
                heapq.heappush(heap, (nd, counter, nxt))
                counter += 1
    if target not in dist:
        return float("inf"), []
    path = [target]
    while path[-1] != source:
        path.append(prev[path[-1]])
    return dist[target], path[::-1]


def test_dijkstra():
    g = {"a": [("b", 1), ("c", 4)], "b": [("c", 1), ("d", 5)], "c": [("d", 1)]}
    assert dijkstra(g, "a", "d") == (3.0, ["a", "b", "c", "d"])
    assert dijkstra(g, "d", "a") == (float("inf"), [])
    assert dijkstra(g, "a", "a") == (0.0, ["a"])
```
O((V + E) log V). Explain lazy deletion, the tie-breaker counter, and why negative weights break the greedy invariant (use Bellman-Ford).

### 7. Comparative Analysis

| Choice | When | Trap |
|---|---|---|
| Hash map vs sorting | O(n) with memory vs O(n log n) with O(1) extra | Forgetting sort mutates input |
| Sliding window vs prefix sums | Monotonic constraints (non-negative) vs arbitrary values | Sliding window with negatives |
| BFS vs DFS | Shortest unweighted path/levels vs reachability/backtracking | DFS for shortest path |
| Dijkstra vs BFS vs Bellman-Ford | Weighted non-negative vs unweighted vs negative weights | Dijkstra with negatives |
| Heap vs sort for top-k | O(n log k) streaming vs O(n log n) | Using max-heap of all n |
| Recursion vs iteration | Clarity vs depth limits | Python recursion limit on 10⁵-depth input |
| Top-down vs bottom-up DP | Easier derivation vs no recursion, space optimization | Unbounded memo memory |
| Union-find vs DFS for connectivity | Dynamic edge additions vs static graph | Forgetting path compression |
| Library (`bisect`, `Counter`, `heapq`) vs manual | Fine after showing understanding | Hiding the algorithm entirely |

### 8. Failure Modes and Debugging

- **Off-by-one in binary search** → write the invariant (`answer in [lo, hi)`), test arrays of size 0, 1, 2.
- **Infinite loop** in `while lo < hi` → ensure progress (`lo = mid + 1` or `hi = mid`).
- **Mutated shared state in backtracking** → copy when recording results.
- **Visited marked too late in BFS** → duplicates and exponential blowup; mark on enqueue.
- **Recursion depth exceeded** → iterative version.
- **Wrong DP base case/order** → print small DP tables; check dependency direction.
- **TLE from hidden O(n) operations** → slicing, `in list`, `pop(0)`, repeated `sum`.

**Debugging technique in interviews:** trace a tiny example by hand, out loud, updating a variable table; compare against expected at each step. Interviewers reward systematic debugging more than first-try correctness.

### 11. Testing Strategy

- **Hand-crafted edge cases**: empty, single, two elements, all equal, sorted/reverse sorted, negatives, max constraints.
- **Brute-force oracle + Hypothesis**:
```python
from hypothesis import given, strategies as st
from problems.prefix_sum.subarray_sum import subarray_sum


def brute(nums, k):
    return sum(1 for i in range(len(nums)) for j in range(i + 1, len(nums) + 1)
               if sum(nums[i:j]) == k)


@given(st.lists(st.integers(-5, 5), max_size=30), st.integers(-10, 10))
def test_matches_brute_force(nums, k):
    assert subarray_sum(nums, k) == brute(nums, k)
```
- **Performance sanity**: run with max-size random input and time it (`time.perf_counter`).

### 13. Interview Preparation

#### Quick Questions
- **Q: Complexity of `heapq.heappush`?** O(log n). Heapify is O(n).
- **Q: When does sliding window not work?** When the window validity isn't monotonic (e.g. negative numbers for sum constraints).
- **Q: BFS vs DFS for shortest path?** BFS in unweighted graphs; DFS doesn't guarantee shortest.
- **Q: How to get a max-heap in Python?** Negate keys or wrap with inverted comparison.
- **Q: What's amortized O(1) append?** Dynamic array over-allocates geometrically; occasional O(n) resize averages to O(1).

#### Intermediate Questions
- **Q: Explain binary search on the answer with an example.** Monotonic feasibility (capacity → can ship in D days); search over the answer range; O(n log range).
- **Q: Top-down vs bottom-up DP?** Memoized recursion is easier to derive and computes only needed states; bottom-up avoids recursion limits and enables space optimization.
- **Q: How do you choose a data structure?** From required operations and their frequency: membership → set; ordered by priority → heap; FIFO → deque; ordered keys → sorted list/bisect or balanced tree; LRU → dict + linked list.

#### Advanced Questions
- **Q: Why does Dijkstra fail with negative edges?** Its greedy invariant (the popped node's distance is final) breaks if a later negative edge can reduce it; use Bellman-Ford (O(VE)) or Johnson's algorithm.
- **Q: Prove the two-pointer 3Sum doesn't miss solutions.** For fixed i, if sum < 0, any pair with current lo and a smaller hi is also < 0 → safe to move lo; symmetric for hi.
- **Q: Union-find complexity?** With path compression + union by rank, O(α(n)) amortized per operation.

#### Coding Questions
Use §9 lists. Signature problems by pattern: Two Sum, 3Sum, Longest Substring Without Repeats, Subarray Sum Equals K, Koko Eating Bananas, Daily Temperatures, LRU Cache, Merge K Lists, Validate BST, Course Schedule, Merge Intervals, Combination Sum, Coin Change, Single Number.

- "Your solution is O(n²) and n = 10⁶. What now?" — Identify repeated work; hash/sort/prefix; discuss memory.
- "The interviewer gives a hint you disagree with." — Explore it respectfully, test it on an example, and explain trade-offs.

### 14. Explain-It-at-Three-Levels

**Sliding window.** *30 s:* Maintain a contiguous window and move both ends forward, so each element is processed at most twice — O(n) instead of O(n²). *2 min:* Template; valid/invalid condition; state maintenance with counts; fixed vs variable windows. *Deep:* Monotonicity requirement, failure with negatives, monotonic deque extension for window max, amortized analysis.

**Dynamic programming.** *30 s:* Break a problem into overlapping subproblems, solve each once, and build the answer from them. *2 min:* State, recurrence, base cases, order, answer; coin change example. *Deep:* Proving optimal substructure, state compression, reconstructing solutions, complexity = states × transitions, when greedy suffices (exchange argument).

**Binary search.** *30 s:* Halve the search space using a monotonic condition — O(log n). *2 min:* first-true template and invariant. *Deep:* search on the answer, real-valued binary search with iteration bounds, off-by-one proofs.

### 16. Common Interview Traps

| Trap | Correct model |
|---|---|
| Jumping to code | Clarify constraints and edge cases first; state the brute force. |
| "Python's `sorted` makes it O(n)" | Sorting is O(n log n). |

### 17. Cheat Sheet

- Method: clarify → examples → brute force → pattern → optimize → implement → test → Big-O.
- Hash: complement lookups; check before insert.
- Two pointers: sorted + move based on comparison; skip duplicates.
- Sliding window: expand right, shrink while invalid; monotonic constraints only.
- Prefix sums: `count[prefix - k]`, base `{0:1}`.
- Binary search: first-true template; `lo = mid + 1`, `hi = mid`; search on answer.
- Monotonic stack: resolve "next greater/smaller" in O(n).
- Heap: `heapq` min-heap; negate for max; size-k heap for top-k.
- Trees: bounds for BST validation; iterative for depth.
- Graphs: BFS (mark on enqueue), Kahn topo sort, Dijkstra (non-negative), DSU.
- Intervals: sort by start; merge when `start <= last_end` (clarify closed/half-open).
- Backtracking: choose/explore/unchoose; copy results; prune.
- DP: state, recurrence, base, order, answer, space.
- Bits: `x & (x-1)`, `x & -x`, XOR pairs, masks, 32-bit `& 0xFFFFFFFF`.
