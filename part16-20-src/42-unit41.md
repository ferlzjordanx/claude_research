## Unit 41 — Spring Coding Interviews

### 1. Learning Objectives

By the end of this unit you will be able to:

1. **Implement** within 60 minutes a Customer CRUD REST API with PostgreSQL, Flyway, Bean Validation, centralized RFC 9457 error handling and meaningful tests.
2. **Extend** it within 90 minutes (cumulative) with JWT-based authentication/authorization, pagination and filtering.
3. **Extend** it within 120 minutes (cumulative) with Kafka event publication, Redis caching and Testcontainers-based integration tests for PostgreSQL, Kafka and Redis.
4. **Plan** timed builds: scope, order of work, checkpoints, and what to cut when time runs short.
5. **Narrate** design choices while coding — layering, DTO/entity separation, transaction boundaries, error semantics, security model, caching and messaging trade-offs — without stalling.
6. **Test** at the right levels (slice tests, Testcontainers integration tests, security tests) within a time budget.
7. **Debug** common live-coding failures quickly (context startup errors, validation not firing, 401/403 confusion, lazy-loading exceptions, cache misses, Kafka test flakiness).
8. **Evaluate** incremental feature additions for backward compatibility and risk.

### 2. Prerequisite Knowledge

- Spring Boot 4 web MVC, Data JPA, validation, Security 7 resource server, Spring for Apache Kafka, Spring Data Redis, Testcontainers (Units 39 §4.7–4.14).
- PostgreSQL basics and Flyway migrations.
- Docker running locally (Testcontainers needs it).
- A prepared project template (see below) — interviewers usually allow you to start from Spring Initializr or a skeleton; *practice with the same template every time*.

**Version notes [Version-dependent].** Spring Boot 4 renamed and modularized several starters: use `spring-boot-starter-webmvc` (the old `spring-boot-starter-web` name may still resolve as a deprecated alias), `spring-boot-starter-flyway` (Flyway auto-configuration now lives in its own module), and per-technology test starters/modules; `@MockBean` is removed — use `@MockitoBean`. Testcontainers 2.x uses `testcontainers-<module>` artifact names and packages like `org.testcontainers.postgresql.PostgreSQLContainer` and `org.testcontainers.kafka.KafkaContainer`. Check the Boot 4 migration guide for your exact minor version and keep your template pinned.

### 3. Mental Model

A timed build is a **vertical slice delivered in increments**, each increment shippable. Interviewers grade: does it run, is it correct, is it tested, is it clean, and can you explain your choices.

```
Minute 0 ─────────── 60 ──────────────── 90 ─────────────────── 120
 [CRUD + DB + validation + errors + tests] [JWT + paging + filter] [Kafka + Redis + Testcontainers]
   ↑ checkpoint: green tests, commit         ↑ checkpoint             ↑ checkpoint
```

Principles:

1. **Working software at every checkpoint.** Commit after each increment; never be mid-refactor at the buzzer.
2. **Thin layers, explicit boundaries.** Controller (HTTP + DTOs) → service (business rules + transactions) → repository (persistence). No entities in API responses.
3. **Test the contract, not the framework.** A few high-value tests per layer beat many trivial ones.
4. **Narrate decisions in one sentence each,** then keep typing: "I'm returning 201 with a Location header because the resource is created synchronously."
5. **Cut scope consciously.** Say what you'd add with more time (e.g., optimistic locking, ETags, outbox).

```java
    public Long getId() { return id; }
    public String getFirstName() { return firstName; }
    public String getLastName() { return lastName; }
    public String getEmail() { return email; }
    public Status getStatus() { return status; }
```

```java
package com.acme.customers;

import com.acme.customers.api.CustomerDtos.CustomerRequest;
import com.acme.customers.api.CustomerDtos.CustomerResponse;
import org.springframework.dao.DataIntegrityViolationException;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

@Service
public class CustomerService {

    private final CustomerRepository repository;

    public CustomerService(CustomerRepository repository) {
        this.repository = repository;
    }

    @Transactional
    public CustomerResponse create(CustomerRequest req) {
        if (repository.existsByEmailIgnoreCase(req.email())) {
            throw new DuplicateEmailException(req.email());           // fast path; DB constraint is the real guard
        }
        try {
            Customer saved = repository.saveAndFlush(
                    new Customer(req.firstName(), req.lastName(), req.email().toLowerCase(), req.status()));
            return CustomerResponse.from(saved);
        } catch (DataIntegrityViolationException e) {
            throw new DuplicateEmailException(req.email());           // race between check and insert
        }
    }

    @Transactional(readOnly = true)
    public CustomerResponse get(long id) {
        return repository.findById(id).map(CustomerResponse::from).orElseThrow(() -> new CustomerNotFoundException(id));
    }

    @Transactional
    public CustomerResponse update(long id, CustomerRequest req) {
        Customer c = repository.findById(id).orElseThrow(() -> new CustomerNotFoundException(id));
        c.update(req.firstName(), req.lastName(), req.email().toLowerCase(), req.status());
        try {
            repository.flush();                                        // surface constraint violations here
        } catch (DataIntegrityViolationException e) {
            throw new DuplicateEmailException(req.email());
        }
        return CustomerResponse.from(c);                               // dirty checking persisted the change
    }

    @Transactional
    public void delete(long id) {
        if (!repository.existsById(id)) throw new CustomerNotFoundException(id);
        repository.deleteById(id);
    }
}
```

```java
package com.acme.customers.api;

import com.acme.customers.CustomerService;
import com.acme.customers.api.CustomerDtos.CustomerRequest;
import com.acme.customers.api.CustomerDtos.CustomerResponse;
import jakarta.validation.Valid;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;
import org.springframework.web.servlet.support.ServletUriComponentsBuilder;

@RestController
@RequestMapping("/api/v1/customers")
public class CustomerController {

    private final CustomerService service;

    public CustomerController(CustomerService service) { this.service = service; }

    @PostMapping
    public ResponseEntity<CustomerResponse> create(@Valid @RequestBody CustomerRequest request) {
        CustomerResponse created = service.create(request);
        var location = ServletUriComponentsBuilder.fromCurrentRequest().path("/{id}")
                .buildAndExpand(created.id()).toUri();
        return ResponseEntity.created(location).body(created);
    }

    @GetMapping("/{id}")
    public CustomerResponse get(@PathVariable long id) { return service.get(id); }

    @PutMapping("/{id}")
    public CustomerResponse update(@PathVariable long id, @Valid @RequestBody CustomerRequest request) {
        return service.update(id, request);
    }

    @DeleteMapping("/{id}")
    public ResponseEntity<Void> delete(@PathVariable long id) {
        service.delete(id);
        return ResponseEntity.noContent().build();
    }
}
```

```java
package com.acme.customers.api;

import com.acme.customers.CustomerNotFoundException;
import org.springframework.http.HttpHeaders;
import org.springframework.http.HttpStatus;
import org.springframework.http.HttpStatusCode;
import org.springframework.http.ProblemDetail;
import org.springframework.http.ResponseEntity;
import org.springframework.orm.ObjectOptimisticLockingFailureException;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;
import org.springframework.web.context.request.WebRequest;
import org.springframework.web.servlet.mvc.method.annotation.ResponseEntityExceptionHandler;

import java.util.Map;
import java.util.stream.Collectors;

@RestControllerAdvice
public class ApiExceptionHandler extends ResponseEntityExceptionHandler {

    @ExceptionHandler(CustomerNotFoundException.class)
    ProblemDetail notFound(CustomerNotFoundException e) {
        return problem(HttpStatus.NOT_FOUND, "Customer not found", e.getMessage());
    }

    @ExceptionHandler(com.acme.customers.DuplicateEmailException.class)
    ProblemDetail duplicate(RuntimeException e) {
        return problem(HttpStatus.CONFLICT, "Duplicate email", e.getMessage());
    }

    @ExceptionHandler(ObjectOptimisticLockingFailureException.class)
    ProblemDetail conflict(ObjectOptimisticLockingFailureException e) {
        return problem(HttpStatus.CONFLICT, "Concurrent update", "The customer was modified concurrently; retry.");
    }

    @Override
    protected ResponseEntity<Object> handleMethodArgumentNotValid(MethodArgumentNotValidException ex, HttpHeaders headers,
                                                                  HttpStatusCode status, WebRequest request) {
        ProblemDetail pd = problem(HttpStatus.BAD_REQUEST, "Validation failed", "One or more fields are invalid.");
        Map<String, String> errors = ex.getBindingResult().getFieldErrors().stream()
                .collect(Collectors.toMap(fe -> fe.getField(), fe -> String.valueOf(fe.getDefaultMessage()), (a, b) -> a));
        pd.setProperty("errors", errors);
        return ResponseEntity.badRequest().body(pd);
    }

    private static ProblemDetail problem(HttpStatus status, String title, String detail) {
        ProblemDetail pd = ProblemDetail.forStatusAndDetail(status, detail);
        pd.setTitle(title);
        return pd;
    }
}
```

```java
import org.springframework.beans.factory.annotation.Value;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.http.HttpMethod;
import org.springframework.security.config.Customizer;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.config.http.SessionCreationPolicy;
import org.springframework.security.oauth2.jose.jws.MacAlgorithm;
import org.springframework.security.oauth2.jwt.JwtDecoder;
import org.springframework.security.oauth2.jwt.NimbusJwtDecoder;
import org.springframework.security.web.SecurityFilterChain;

import javax.crypto.spec.SecretKeySpec;
import java.nio.charset.StandardCharsets;

@Configuration
public class SecurityConfig {

    @Bean
    SecurityFilterChain api(HttpSecurity http) throws Exception {
        return http
                .csrf(c -> c.disable())
                .sessionManagement(s -> s.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
                .authorizeHttpRequests(a -> a
                        .requestMatchers("/actuator/health/**").permitAll()
                        .requestMatchers(HttpMethod.GET, "/api/v1/customers/**").hasAuthority("SCOPE_customers:read")
                        .requestMatchers("/api/v1/customers/**").hasAuthority("SCOPE_customers:write")
                        .anyRequest().authenticated())
                .oauth2ResourceServer(o -> o.jwt(Customizer.withDefaults()))
                .build();
    }

    /** Interview/demo only: HMAC key. Production: spring.security.oauth2.resourceserver.jwt.issuer-uri (JWKS, RS256/ES256). */
    @Bean
    JwtDecoder jwtDecoder(@Value("${app.jwt.secret}") String secret) {
        var key = new SecretKeySpec(secret.getBytes(StandardCharsets.UTF_8), "HmacSHA256");
        return NimbusJwtDecoder.withSecretKey(key).macAlgorithm(MacAlgorithm.HS256).build();
    }
}
```

Narration: "Symmetric keys mean every service that verifies can also mint tokens — fine for the exercise, not for production; I'd use the IdP's JWKS and validate audience too (`spring.security.oauth2.resourceserver.jwt.audiences`)."

```java
package com.acme.customers;

import org.springframework.data.jpa.domain.Specification;

import java.time.Instant;

public final class CustomerSpecs {

    public record Filter(Customer.Status status, String lastNamePrefix, String emailContains, Instant createdAfter) { }

    public static Specification<Customer> matching(Filter f) {
        Specification<Customer> spec = (root, query, cb) -> cb.conjunction();
        if (f.status() != null) {
            spec = spec.and((root, q, cb) -> cb.equal(root.get("status"), f.status()));
        }
        if (f.lastNamePrefix() != null && !f.lastNamePrefix().isBlank()) {
            String prefix = escapeLike(f.lastNamePrefix().toLowerCase()) + "%";
            spec = spec.and((root, q, cb) -> cb.like(cb.lower(root.get("lastName")), prefix, '\\'));
        }
        if (f.emailContains() != null && !f.emailContains().isBlank()) {
            String pattern = "%" + escapeLike(f.emailContains().toLowerCase()) + "%";
            spec = spec.and((root, q, cb) -> cb.like(root.get("email"), pattern, '\\'));
        }
        if (f.createdAfter() != null) {
            spec = spec.and((root, q, cb) -> cb.greaterThan(root.get("createdAt"), f.createdAfter()));
        }
        return spec;
    }

    private static String escapeLike(String s) {
        return s.replace("\\", "\\\\").replace("%", "\\%").replace("_", "\\_");   // user input is data, not wildcards
    }

    private CustomerSpecs() { }
}
```

```java
private static final java.util.Set<String> SORTABLE = java.util.Set.of("lastName", "createdAt", "email");

@GetMapping
public PageResponse<CustomerResponse> list(@RequestParam(required = false) Customer.Status status,
                                           @RequestParam(required = false) String lastName,
                                           @RequestParam(required = false) String email,
                                           @RequestParam(required = false) java.time.Instant createdAfter,
                                           @org.springframework.data.web.PageableDefault(size = 20, sort = "lastName")
                                           org.springframework.data.domain.Pageable pageable) {
    if (pageable.getPageSize() > 100) throw new IllegalArgumentException("size must be ≤ 100");
    pageable.getSort().forEach(o -> {
        if (!SORTABLE.contains(o.getProperty())) throw new IllegalArgumentException("cannot sort by " + o.getProperty());
    });
    return service.list(new CustomerSpecs.Filter(status, lastName, email, createdAfter), pageable);
}
```

```java
// In CustomerService
@Cacheable(cacheNames = "customers", key = "#id")
@Transactional(readOnly = true)
public CustomerResponse get(long id) { ... }

@CacheEvict(cacheNames = "customers", key = "#id")
@Transactional
public CustomerResponse update(long id, CustomerRequest req) { ... }

@CacheEvict(cacheNames = "customers", key = "#id")
@Transactional
public void delete(long id) { ... }
```

Narration: "Both annotations are proxy-based, so calls from inside the service bypass them. Eviction happens when the method returns — slightly before commit with the transactional proxy ordering, so a concurrent read could re-cache the old value. For strictness I'd evict in an after-commit listener; for this exercise, TTL bounds staleness." Also: "In a multi-tenant app the key must include the tenant."

#### 4.5 Narrating Design Choices While Coding

**Why it matters.** Interviewers can't read your mind; silence looks like being stuck, and unexplained choices look accidental. Narration also lets the interviewer redirect you early.

**Technique — "decision, reason, alternative" in one breath:**

- "DTO records separate from the entity — so API changes don't leak schema and I avoid lazy-loading in serialization; the alternative is projections, which I'd use for read-heavy lists."
- "`@Transactional` on the service, read-only for queries — the controller stays HTTP-only."
- "The database unique constraint is the real guard; the `exists` check only gives a nicer error and has a race."
- "409 for duplicate email, 400 for validation, 404 for missing — consistent ProblemDetail bodies."
- "Scopes map to authorities; method-level `@PreAuthorize` would be my next step for object-level rules."
- "Publishing after commit; outbox if delivery must be guaranteed."
- "Caching DTOs with TTL; eviction on writes; tenant would be part of the key."

**When stuck:** say what you're checking ("I'm getting a 401 in the test — probably the security config isn't in the slice; let me import it"). Show your debugging method.

**Pacing rules.** Never spend more than ~5 minutes on one bug without telling the interviewer and proposing a workaround; prioritize a green build over extra features; leave 5 minutes for a wrap-up summary of what's done, what's missing and how you'd productionize.

### 5. Internal Mechanics — What Happens During These Builds

```
Startup:
  @SpringBootApplication → component scan + auto-configuration (DataSource, JPA EntityManagerFactory, Flyway,
  MVC, Security filter chain, Kafka, Redis, Cache) → Flyway migrates before JPA validates schema (ddl-auto=validate)
  → proxies created: @Transactional (TransactionInterceptor), @Cacheable/@CacheEvict (CacheInterceptor),
    @TransactionalEventListener registered
Request (POST /customers with JWT):
  SecurityFilterChain: BearerTokenAuthenticationFilter → JwtDecoder (signature, exp) → JwtAuthenticationConverter
  (scope claim → SCOPE_ authorities) → AuthorizationFilter (requestMatchers rules)
  → DispatcherServlet → HandlerMapping → argument resolution: Jackson reads body → @Valid triggers Bean Validation
     (MethodArgumentNotValidException → advice → 400 ProblemDetail)
  → CustomerService proxy: CacheInterceptor (no-op for create) → TransactionInterceptor begins tx
  → repository.saveAndFlush → INSERT; constraint violation → DataIntegrityViolationException (translated)
  → publishEvent → held until commit → commit → AFTER_COMMIT listener → KafkaTemplate.send (async)
  → response 201 + Location
```

Interceptor ordering on the same method (transaction vs cache) is controlled by advisor order; by default both have lowest precedence, so don't rely on implicit ordering for correctness-sensitive behavior — use after-commit eviction where it matters.

### 13. Interview Preparation

#### Quick Questions

1. **Why DTOs instead of entities in responses?** Decouple API from schema, avoid lazy-loading and over-exposure, control validation and versioning.
2. **What does `@Valid` do on a request body?** Triggers Bean Validation after Jackson deserialization; failures raise `MethodArgumentNotValidException` → 400.
3. **Why `open-in-view: false`?** Prevents lazy loading during serialization and holding DB connections for the whole request.
4. **What's `@ServiceConnection`?** Boot creates connection details from a Testcontainers container — no manual property wiring.
5. **401 vs 403 in your tests?** Missing/invalid token vs insufficient scope.

#### Intermediate Questions

**Q: Walk me through what happens when POST /customers is called with a duplicate email.**
*Strong answer:* Security validates the JWT and scope; Jackson deserializes; Bean Validation passes; the service's transaction starts; the `exists` check may pass under a race; `saveAndFlush` hits the unique constraint; Spring translates to `DataIntegrityViolationException`; the service maps it to `DuplicateEmailException`; the advice returns 409 ProblemDetail; the transaction rolls back; no event is published because the after-commit listener never fires.

**Q: How would you make pagination scale to millions of rows?**
*Strong answer:* Keyset pagination on an indexed, unique ordering (`(last_name, id)`), no total count (or approximate), cursor tokens encoding the last key; Spring Data `Window`/`ScrollPosition` or custom query; allow-listed sort fields.

**Q: How do you keep the cache consistent?**
*Strong answer:* Cache DTOs with TTL; evict on update/delete; after-commit eviction to avoid races; include tenant/user context in keys; never cache authorization results without care; monitor hit rate.

#### Advanced Questions

**Q: Your event is published after commit. What can go wrong and how would you fix it?**
*Strong answer:* Process crash or Kafka outage after commit loses the event (dual-write problem). Fix with a transactional outbox (same transaction), relay with retries, idempotent consumers keyed by event id; or CDC with Debezium.

**Q: How would you add object-level authorization (users only see customers they own)?**
*Strong answer:* Ownership column; derive user from `Jwt` subject; enforce in repository queries (`findByIdAndOwnerId`), or `@PostAuthorize`/custom `AuthorizationManager` checks; 404 for not-owned to avoid enumeration; tests for cross-user access.

#### Coding Questions

1. Implement `ApiExceptionHandler` with validation, not-found, conflict and generic 500 handling (without leaking internals).
2. Implement a Specification filter with escaped LIKE input.
3. Write a `@WebMvcTest` proving `customers:read` cannot POST.
4. Write a Testcontainers test asserting a Kafka event is published once per create.

#### Scenario Questions

**Q: The interviewer asks you to add soft delete in 10 minutes.** *Strong answer:* Add `deleted_at` column (migration), set it in delete, filter in queries (Hibernate `@SoftDelete` in 6.4+/7 or `@SQLRestriction`), adjust unique constraint (partial unique index `WHERE deleted_at IS NULL`), evict cache, publish `CustomerDeleted`, tests for 404 after delete and email reuse.

### 15. Knowledge Check

**Conceptual**
1. Why is the database unique constraint necessary even with an `existsByEmail` check?
2. Why publish events in an `AFTER_COMMIT` listener rather than inside the transaction?
3. What does `@ServiceConnection(name = "redis")` do on a `GenericContainer`?
4. Why should sort fields be allow-listed?
5. Why might `@CacheEvict` on a transactional method still allow stale cache entries?

**Code reading**
6. Why does `createdAt` come back null in the integration test, and how do you fix it?
7. What's wrong with `cb.like(root.get("email"), "%" + input + "%")`?
8. What happens if `CustomerFlowIT.Listener` uses `auto-offset-reset=latest` with a fresh group id?

**Debugging**
9. All `@WebMvcTest` tests return 401 after adding security. Why and how to fix?
10. After upgrading to Boot 4, Flyway stopped running. Why?

**Design**
11. When would you choose PATCH over PUT for customer updates, and how would you implement it safely?
12. How would you make `POST /customers` safe to retry?

### Knowledge Check Answers

1. Check-then-insert races between concurrent requests; only the constraint is atomic and authoritative.
2. To avoid publishing events for data that rolls back; the listener runs only after a successful commit (but can still lose events on crash — outbox fixes that).
3. Tells Boot the container provides a Redis service connection (it can't infer from a generic image otherwise), so Boot configures `spring.data.redis` connection details automatically.
4. Arbitrary properties can expose internal fields, cause errors (unknown property → 500) or enable expensive unindexed sorts.
5. Eviction can occur before the transaction commits (interceptor ordering), so a concurrent reader can reload and re-cache the old committed value; evict after commit.
6. The column is DB-generated and `insertable=false`; Hibernate doesn't re-read it after insert. Use `@Generated` (Hibernate) or set it in Java from a `Clock`, or refresh the entity.
7. Unescaped user input turns `%`/`_` into wildcards (pattern injection, expensive scans); also no lower-casing for case-insensitive search. Escape and specify the escape character.
8. The consumer may start after the event was produced and never see it → the test times out. Use `earliest` for test groups.
9. The security filter chain is active in the slice and requests have no token; add `.with(jwt().authorities(...))` (and import the security config so rules match production).
10. Boot 4 moved Flyway auto-configuration into a separate module; add `spring-boot-starter-flyway` (plus the database-specific Flyway artifact).
11. When clients update few fields or bandwidth matters; implement with JSON Merge Patch semantics (absent = unchanged, null = clear), validate the merged result, and use optimistic locking/ETags to prevent lost updates.
12. Require an `Idempotency-Key` header; store key + request hash + response in a table claimed in its own transaction; replay on duplicates; 409 while in progress; 422 on mismatched body (Unit 38).
